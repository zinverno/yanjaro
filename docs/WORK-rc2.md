## Причина play/pause

В rc1 `Controller._load_track` вызывал `Player.stop()`, который присваивал `paused=True`, не меняя свойство mpv `pause`. Если движок уже имел `pause=False`, следующая команда `set pause no` не создавала нового уведомления. Получался звук при оставшемся UI-состоянии паузы. Проверка с настоящим libmpv/WAV/`ao=null` и настоящим QML воспроизвела ошибку до исправления; это не проверка слышимого звука аккаунта.

Исправление: исходная синхронизация наблюдаемых свойств на `file-loaded`, отсутствие выдуманной паузы в `stop()`, Qt queued signals и привязка file lifecycle к `playlist_entry_id`. Сетевые поколения запроса сохранены отдельно. `loadfile` в фактическом mpv 0.41 возвращает ID до загрузки файла; подтверждено локальным probe без аккаунта/URL в выводе.

Контракты: [mpv](https://mpv.io/manual/stable/), [MPRIS Player](https://specifications.freedesktop.org/mpris/latest/Player_Interface.html), [MPRIS root](https://specifications.freedesktop.org/mpris/latest/Media_Player.html), [QtDBus](https://doc.qt.io/qtforpython-6/PySide6/QtDBus/index.html), [Secret Service](https://specifications.freedesktop.org/secret-service/latest/), [keyring](https://keyring.readthedocs.io/en/stable/).

## A: конечная очередь и управление

Общая модель переименована в PlaybackController. Режимы repeat/shuffle применяются к полной ID-очереди любимого; история фактически запущенных треков отделена от оставшегося порядка. Пауза во время загрузки сохраняется; Stop инвалидирует позднюю подгрузку радио. В радио режимы отключены, настройки конечной очереди сохранены. Один клик/Enter запускает строку; повторный выбор текущего трека возобновляет паузу без перезапуска. Панель центрирована относительно всего окна, иконка repeat-one содержит «1».

Автоматически: 34 теста PASS, в том числе реальные libmpv/QML pause/seek/EOF, виртуализация, click/drag/right click, полная коллекция 60 ID, shuffle-off/Previous, EOF vs Next, одиночная/пустая очередь, пауза загрузки и три партии станции с ошибкой/повтором. Макеты SYNTHETIC при 1024×700, 1366×768, 1920×1080 проверяют центр и границы. Реальный аккаунт и слышимое соответствие нового UI: NOT RUN на этом шаге.

## A: сохранение входа и MPRIS

Добавлены явный Secret Service backend (SecretStorage), асинхронное чтение/запись/удаление, настройки запоминания, отказ без plaintext fallback, повтор после ошибки сети, разделение 401/403 до SDK и поколение аккаунта для всех ответов. MPRIS использует тот же PlaybackController и Qt event loop, с точными D-Bus типами через Jeepney (причина выбора после оценки QtDBus — в DESKTOP-INTEGRATION.md).

Автоматически: 41 тест PASS. Отдельно storage save/restore/delete/locked/cancel/network и отсутствие автостарта; MPRIS XML/typed wire messages, команды, отсутствие Position floods, Seeked и запрет радио-режимов; libmpv+QML rapid A→C, пауза загрузки, ошибочный файл и double-click без повторного запуска. Полная D-Bus-сессия BLOCKED политикой sandbox (socket bind). Реальный Secret Service, карточка оболочки и звук аккаунта после изменений: NOT RUN, подготовлена приёмка. Старые PASS rc1 сюда не перенесены.

## B: каталог и сущности

Каталог группируется консервативно по типу ID и parent_id, без анализа русских названий; неизвестные остаются в «Других». Локальные pins/hidden/recent отделены по UID, порядок обновляется при открытии раздела/действии пользователя, не на каждом треке. Dashboard не выдаётся за проверенную персонализацию и пока не используется. Station.icon проходит allowlist публичных CDN, fallback — собственные SVG по категории; Qt загружает изображения независимо от аудио, дисковый кэш ограничен 32 МБ.

Поиск all/track/artist/album использует настоящие методы SDK. «Все» показывает лучший результат и до шести результатов каждого реализованного типа; полная пагинация — на вкладках типов. Исполнитель: brief_info + страница треков, реальные альбомы из brief_info и отдельный список direct_albums. Альбом: volumes в серверном порядке, недоступные треки отмечены. Назад сохраняет вкладку/запрос/scroll. Навигация и inline-ссылки не заменяют очередь. Очередь любимого полная по ID; очередь исполнителя относится к явно показанным загруженным трекам.

Автоматически проверены реальные SDK de_json-форматы поиска/альбомов, несколько исполнителей, два диска/недоступный трек, неизвестные станции и региональный дочерний ID, pins/hidden/filter, поздний ответ другой вкладки, Back и пустой ответ. Живые ответы новых entity endpoints и фактические Station.icon аккаунта: NOT RUN до приёмки кандидата; документация SDK не считается такой проверкой.

Дополнительная проверка inline-ссылок нашла нулевую ширину кнопки исполнителя из-за циклического ограничения Layout.maximumWidth относительно родителя. Удалено это ограничение, реальный QTest mouseClick теперь открывает исполнителя и не запускает строку. Проверка виртуализации обходит visual children ListView, а не только QObject-владельцев делегатов. Все 44 проверки этапов A/B проходят; геометрия трёх базовых размеров также PASS на синтетических данных.

## C: опциональный конечный микс

Реализован отдельный локальный отбор, без вызова «Моей волны»: полный пул ID любимого → ограниченная выборка метаданных → до двух исполнителей и одного альбома → фильтры/ранжирование/разнообразие → до 30 треков. Кандидаты имеют происхождение и правдивую причину. Отдельные локальные оценки, seed-треки, баланс знакомого/нового, отключение и очистка. Данные по аккаунту, 90-дневная очистка событий/оценок при следующем запуске/записи. Similar endpoints до живой проверки не включены.

Учёт интервалов уточнён на переходах состояния движка (в том числе seeking); EOF/report/feedback сохраняют однократность. Тесты передачи искусственно заданных 2.5/12.5 секунд допускают до 50 мс действительного времени между присвоением и событием; точные интервалы отдельно проверены контролируемыми монотонными часами. 48 тестов PASS, включая отдельные проверки C и MPRIS Next через три API-партии с однократными started/skip/finished. Качество и реальный микс аккаунта NOT RUN, не заявляется превосходство над Яндексом.
