## Изменения

Общий кэш полных liked ID, API add/remove с сохранением `track:album`, проверка bool результата SDK 3.2.0, оптимистичная отметка/откат и блокировка повторного клика. Запросы идут через существующий worker; мутации автоматически не повторяются. Logout/close отменяют ещё не начавшиеся операции; ответ уже отправленного запроса не попадает в новый сеанс. Уже принятую сервером мутацию отмена локального запроса не может отозвать.

После успешной мутации заново загружается первая страница коллекции с актуальными ID/количеством; очередь воспроизведения остаётся снимком исходного контекста. Сердечки используют единое состояние и SVG. Альбом доступен из меню строки, исполнитель остаётся ссылкой. Ссылка альбома в широком плеере сохранена. Исправлено повторное открытие Drawer при клике по кнопке закрываемой очереди; причина — `opened` менялся до окончания анимации, теперь переключение учитывает `visible`.

## Короткая ручная приёмка — NOT RUN

По инструкции владельца архива сначала отдельно согласовать установку rc3 и изменение любимого. Основная система пока остаётся на rc2-2. После согласования:

1. Выбрать один тестовый трек, записать его исходную отметку. Добавить из поиска: музыка не должна запускаться от сердечка; проверить отметку в плеере, любимом и на странице альбома.
2. Закрыть/открыть приложение и проверить сохранённую отметку; убрать лайк, повторить проверку после перезапуска. В конце восстановить исходное состояние трека.
3. Во время воспроизведения проверить основную строку, сердечко, меню → альбом, узкое окно и открытие/закрытие очереди. Добавление/удаление не должно прерывать музыку или заменять очередь.

Не требуется повтор всей прошлой приёмки станций, поиска, MPRIS и входа. Headless UI и ответы синтетического транспорта не доказывают успешную мутацию на Яндексе. Ошибка API может означать, что результат на сервере неизвестен: явное обновление любимого сверяет состояние; слепой сетевой повтор для этой операции не вводится.
