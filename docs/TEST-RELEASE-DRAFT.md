# Yanjaro 0.2.0rc2 — первый публичный тест (черновик, не опубликован)

Неофициальный клиент Yandex Music / Яндекс Музыки для Manjaro x86_64. Это предварительный выпуск для ограниченного тестирования, не стабильная 0.2.0 и не обещание поддержки всех Linux.

Рабочие возможности: любимое, поиск треков/исполнителей/альбомов, страницы каталога, станции и «Моя волна» с продолжением, постоянный плеер и очередь, repeat/shuffle для конечных списков, сохранение аккаунта через Secret Service и MPRIS. Добровольный «Подбор Yanjaro · эксперимент» собирает конечный микс из каталога по локальным правилам; превосходство над «Моей волной» не доказано.

Нужен аккаунт с доступом к полным трекам: подписка и региональные ограничения определяются сервисом. Клиент не обходит ограничения доступа и не заменяет полный трек превью. Подтверждён сценарий аккаунта владельца; универсальная совместимость аккаунтов не заявляется.

Проверенная живая среда: Manjaro Stable x86_64, Python 3.14.7, Qt/PySide6 6.11.2, mpv 0.41, SDK 3.2.0; установленная ревизия `0.2.0rc2-2`. Новый `-3` меняет упаковку/атрибуцию и отчётность, Python/QML без изменения. Результат чистой установки `-3` необходимо перенести из PUBLIC-TEST-PREP.md перед публикацией; наличие пакета не означает её успеха.

Для обычного пользователя предназначены только:

- `yanjaro-0.2.0rc2-3-any.pkg.tar.zst` — пакет для проверяемой Manjaro Stable;
- `yanjaro-0.2.0rc2.tar.gz` — точно соответствующий архив исходников;
- `SHA256SUMS` и манифест происхождения (commit, сборочная среда).

Ссылок на скачивание пока нет: GitHub Release не создан. После отдельного разрешения и публикации всех файлов сверить SHA-256, затем в папке загрузки:

```sh
sha256sum -c SHA256SUMS
sudo pacman -U ./yanjaro-0.2.0rc2-3-any.pkg.tar.zst
/usr/bin/yanjaro
```

Пакет зависит от системных Qt/mpv/Secret Service и Python-библиотек; pacman должен разрешить их из репозиториев Manjaro. Это не автономный установщик. Закройте старое окно до обновления. Запуск доступен из меню Yanjaro Music. Удаление: `sudo pacman -Rns yanjaro`, предварительно проверьте предлагаемый список пакетов. Выход в приложении удаляет сохранённый секрет; удаление пакета само не очищает личные XDG-данные/связку ключей.

Токен хранится только в системном Secret Service, пароль не сохраняется. При недоступном хранилище доступен явно обозначенный сеансовый вход. Настройки находятся в `$XDG_CONFIG_HOME/yanjaro`, локальные данные — `$XDG_STATE_HOME/yanjaro`, кэш обложек — `$XDG_CACHE_HOME/yanjaro`; стандартные пути: `~/.config`, `~/.local/state`, `~/.cache`. Данные эксперимента отделены по аккаунту, ограничены 90 днями, очищаются в настройках.

Каталог, аудио и отчёты прослушивания/радио обращаются к Яндексу. Отдельного сервера аналитики Yanjaro в проверенном коде нет; это не заявление об отсутствии любых сетевых обращений. История сервиса скрыта; offline, lossless и Ynison не реализованы. Repeat/shuffle отключены для бесконечных станций. После одного ограниченного повтора сети окончательная ошибка остаётся видимой; внешняя причина прежнего ConnectTimeout не установлена.

Об ошибке можно сообщить в Issues репозитория: версия из `pacman -Q yanjaro`, окружение, действия, ожидаемое/фактическое поведение и безопасный текст сообщения. Не прикладывайте токены, cookies, коды входа, аудиоссылки, дампы HTTP, keyring, личные базы и полный рабочий стол с уведомлениями. Перед отправкой снимка проверьте личные сведения.

Wheel/sdist остаются дополнительным способом для разработчиков: они не включают системные Qt/mpv-зависимости в автономный установщик. Git bundle, логи диагностики и пользовательские профили в Release не включать.

Перед публикацией удалить пометку «черновик» только после фактической приёмки и отдельного разрешения владельца; добавить проверенные ссылки, точный SHA-256 и актуальные ограничения. Не создавать фиктивный тег/ссылку и не переносить PASS старого пакета на новый.
