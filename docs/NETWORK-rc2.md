# Подготовка аудио: живая ошибка и ограниченный повтор

На установленном rc2-1 владелец сообщил о частой ошибке при запуске/переключении песен, в том числе «Моей волны»: «Сеть недоступна или истёк таймаут». Ручное «Продолжить» помогало. Сам текст не позволял отличить таймаут от HTTP-отказа: SDK NetworkError также включает некоторые HTTP-ошибки.

Отдельный явно запущенный диагностический процесс использовал код установленного приложения без изменения его поведения. Собирались только этап, категория исключения, HTTP-код при наличии и длительность. URL, ID треков/аккаунта, заголовки, ответы, токены и текст исходных исключений не записывались.

Наблюдение с реальным аккаунтом 2026-10-07:

| Этап | Результат | Транспорт | HTTP-код | Время |
|---|---|---|---|---|
| Получение вариантов аудио (`tracks_download_info`) | timeout | ConnectTimeout | отсутствует | 8011 мс |

До этого шесть последовательных подготовок трека успешно выполнили все три запроса примерно за 70–160 мс каждый. В диагностике есть успешные подготовки после сбоя. Это доказывает таймаут установления соединения с API до запуска mpv; причина нестабильности маршрута/сервиса не установлена. Не заявляется, что libmpv, shuffle или API лимит вызвали этот сбой.

Исправление клиента: один повтор **на всю подготовку** только для timeout/временного сбоя соединения или HTTP 408/500/502/503/504. Через 400 мс в worker повторяется только неуспешный читающий запрос; успешно полученные метаданные не запрашиваются заново. Максимум четыре запроса вместо обычных трёх. Основной таймаут 8 секунд не увеличен. Ошибка TLS, авторизации, HTTP 4xx (кроме 408), включая 429, не получает слепых повторов. Device Flow сохраняет контракт SDK для HTTP 400/authorization_pending.

Смена песни, станции, Stop, logout и закрытие устанавливают Event отмены: ожидание повтора прерывается, следующий шаг старой подготовки не запускается. Уже выполняющийся сетевой вызов заканчивается по обычному таймауту; поколения запросов по-прежнему отбрасывают его результат. Пауза в загрузке сохраняется. Feedback/отчёты прослушивания и остальные запросы не повторяются этим механизмом, поэтому он не создаёт вторые skip/finished.

При окончательном отказе ошибка указывает этап подготовки. HTTP-отказ и rate limit больше не выдаются за отсутствие сети. Секреты в текст сообщения не попадают.

Регрессия до изменения: transient failure прерывала stream, хотя следующий ответ был успешным. После изменения: fail-once→success, один общий предел повторов, отмена, отсутствие повторов 400/404/429, Device Flow pending, A→B во время сбоя без повтора A и сохранённая пауза B. Полный набор — 51 тест PASS, включая прежние mpv/QML и три партии радио/MPRIS с однократным feedback. Живая проверка нового пакета отмечается отдельно в VALIDATION.md: результаты старого rc2-1 не считаются доказательством автоматического восстановления.

После согласованного обновления rc2-2: 21 успешная подготовка (63 запроса), волна сыграла треки из пяти разных партий, владелец подтвердил переходы без ручного повтора. Ошибка в этой живой сессии не возникла. Автоматическое восстановление проверено синтетически; на реальном повторном сбое ещё не наблюдалось. Не заявляется устранение внешней причины ConnectTimeout или гарантия отсутствия будущих ошибок.
