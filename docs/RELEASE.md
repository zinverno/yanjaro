## Сборка и проверки

`prepare-native.py` формирует снимок текущего дерева; для воспроизведения rc4-1 запускать его **только из экспорта коммита e9a094a**, с `SOURCE_DATE_EPOCH=1791450957`. Обычный `build-native.sh` на более позднем HEAD не воспроизводит принятую документацию/архив и не должен заменять release assets.

Для чистой проверки использовать существующие `scripts/check-clean.sh arch` и `scripts/check-clean.sh manjaro` на доступном Docker-хосте либо GitHub Actions. `prepare-clean.py` сам экспортирует полные закреплённые SHA, проверяет manifest и запрещает расхождение runtime-кода/тестов текущей ветки с замороженным кандидатом. Все установки происходят в одноразовых контейнерах. Основная ОС не используется как контейнер.

Workflow предназначен для push в main, PR в main и ручного запуска после его интеграции в default branch. Он не публикует файлы, не создаёт теги и не получает секреты. До интеграции проверяется тот же harness на подготовительной ветке; реальный main-run выполняется после разрешённых merge. При изменении функций нужен новый кандидат/manifest; зелёный frozen build не должен скрывать изменённый код HEAD.

## AUR

Окончательные подготовленные файлы: [packaging/aur/PKGBUILD](../packaging/aur/PKGBUILD), [сгенерированная .SRCINFO](../packaging/aur/.SRCINFO). В отличие от локального `packaging/PKGBUILD`, AUR-рецепт имеет два реально доступных публичных source: GitHub codeload полного commit SHA и официальный SDK wheel с files.pythonhosted.org. Анонимное скачивание проверяется без токенов. Все файлы канонического исходника и устанавливаемый payload должны совпадать с кандидатом.

```sh
# В отдельной Arch-среде с объявленными зависимостями, без root для makepkg:
cd packaging/aur
makepkg --printsrcinfo > .SRCINFO
makepkg --cleanbuild --syncdeps --check
```

`--syncdeps` в этой инструкции может устанавливать зависимости через pacman; агент на основной ОС это не выполняет. CI ставит зависимости штатно внутри каждой изолированной системы и выполняет полный `makepkg --force --cleanbuild --noconfirm` без bypass-флагов. Перед AUR повторно проверить доступность имени, точный diff рецепта/.SRCINFO и отдельное разрешение. Поиск Pamac возможен после публикации/получения метаданных, наличие .desktop не заменяет каталог AUR.

## Установка после публикации или отдельного согласования

В папке скачанных проверенных файлов:

```sh
sha256sum -c SHA256SUMS
sudo pacman -U ./yanjaro-0.2.0rc4-1-any.pkg.tar.zst
pacman -Q yanjaro
/usr/bin/yanjaro
```

До обновления закрыть старое окно. Зависимости Qt/Python/mpv разрешаются из настроенных репозиториев Manjaro; `.pkg.tar.zst` не автономный установщик. Аудиодвижок требует mpv>=0.41, безопасное хранилище — провайдера Secret Service. Для запуска не нужны терминал, venv, исходный каталог, playerctl или расширение оболочки.

Удаление: `sudo pacman -Rns yanjaro`, предварительно проверить предлагаемый список. Logout в приложении удаляет сохранённый секрет; удаление пакета само не очищает пользовательскую связку ключей и XDG-данные. Обновление не удаляет вход и настройки. Исторические детали rc1/rc2/rc3 сохранены в отдельных отчётах и Git; их старые NOT RUN не заменяют актуальную матрицу.
