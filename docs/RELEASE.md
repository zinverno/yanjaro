Публикация, видимость репозитория, merge, теги, Release и AUR не изменяются. Реальный private remote — https://github.com/zinverno/yanjaro. Текущая работа идёт от UI-ветки rc1 в `feature/player-polish-and-discovery`, Git-клон `/tmp/yanjaro-git`; защищённая `.git` основной рабочей папки не меняется. Лицензия владельца GPL-3.0-or-later сохранена.

## Сборка

```sh
./scripts/build-native.sh
```

Сценарий создаёт воспроизводимый архив исходников из белого списка, подставляет SHA-256 в PKGBUILD, генерирует `.SRCINFO` через `makepkg --printsrcinfo`, выполняет **полный** `makepkg --force --cleanbuild` с check() и пишет контрольные суммы. Он не вызывает sudo/pacman/pip для установки зависимостей, не публикует артефакты. Python-ресурсы Qt Quick и SVG устанавливаются независимо от cwd. Архив source локальный, не плавающая ветка/выдуманный тег; пока нет разрешённого публичного immutable URL, рецепт не готов для отправки в AUR.

Native-зависимости: Python 3.11–3.14, PySide6 6.8–6.x, Qt Quick/SVG/Wayland, python-mpv >=1.0.8, **mpv>=0.41**, requests/PySocks/typing-extensions, **python-secretstorage>=3.5 и python-jeepney>=0.9**. SecretStorage подтягивает cryptography/cffi. Провайдер `org.freedesktop.secrets` требуется для сохранённого входа; без него возможен только сеанс с явной ошибкой хранилища. Не требуется GNOME-расширение или playerctl runtime-зависимость. SDK 3.2.0 включён неизменённым отдельным модулем из официального wheel с SHA-256 и лицензией. AUR-зависимостей нет.

Изолированная проверка rc2 использует базовую Manjaro Stable с системными Python 3.14.7 / Qt 6.11.2 / mpv 0.41.0, внешний venv `--system-site-packages` и два проверенных пакета SecretStorage/Jeepney только в `/tmp`. Их SHA-256 сверены с существующей pacman sync database. В namespace накладывается копия local package database с этими двумя пакетами; основная база и системный Python остаются неизменны. Полная сборка в таком окружении не является чистой VM/chroot и не заменяет установочную приёмку.

## Установка после отдельного согласования

Владелец отдельно согласовал и установил rc2-1. Новый rc2-2 исправляет поведение при временном отказе подготовки аудио, не добавляет зависимостей; перед обновлением требуется отдельное согласование. Команда для rc2-2:

```sh
sudo pacman -U /home/zinvernix/projects/yanjaro-music/dist/native/yanjaro-0.2.0rc2-2-any.pkg.tar.zst
pacman -Q yanjaro
/usr/bin/yanjaro
```

После установки приложение доступно из меню Yanjaro Music. Файл `.pkg.tar.zst` не автономный установщик: зависимости разрешаются из настроенных репозиториев. До обновления закрыть старое окно. Для удаления — `sudo pacman -Rns yanjaro`, предварительно проверить предложенный список. Выход в приложении удаляет сохранённый секрет Yanjaro; удаление пакета само не удаляет личное хранилище или XDG-данные. Очистка эксперимента доступна в настройках. Обновление пакета не удаляет вход, настройки и локальные данные.

## Короткая живая приёмка

1. Первый вход с запоминанием. В любимом один клик запускает, клик по текущему не сбрасывает позицию; пауза/продолжение соответствуют слышимому звуку и иконке. Громкость/mute/seek, длинное имя, открытая очередь и маленькое окно.
2. Repeat-one на естественном конце, ручной Next, shuffle/Previous/shuffle-off; полный список любимого. В станции режимы отключены и возвращаются после обычного списка.
3. Закрыть → запуск из меню без браузера. Проверить повторный запуск (одно окно/карточка), сворачивание и закрытие. Затем logout → запуск без входа. Новый сеанс ОС и обновление поверх кандидата — отдельно по возможности.
4. Реальная карточка оболочки с названием/обложкой и управлением обоих направлений; `playerctl` при наличии. [Команды и ограничения](DESKTOP-INTEGRATION.md).
5. Станции: значки, группы, pins/скрытие/отмена, полный локальный поиск. Волна должна начать треки минимум из **трёх** API-партий. Проверить Next через MPRIS без двойного skip.
6. Поиск: вкладка исполнителей → исполнитель → альбом → песня → назад к тому же запросу/вкладке/прокрутке. Отдельно вкладка альбомов и недоступный трек.
7. Эксперимент включить явно, собрать реальный конечный микс, проверить причины и локальные оценки/выключение. Качество оценивать несколькими сессиями рядом с обычным shuffle, без неподтверждённых процентов улучшения.
8. Потеря сети и повтор после восстановления — только в разрешённой среде. Заблокированное/отсутствующее хранилище проверять на отдельной тестовой записи/среде, не повреждая пользовательские ключи.

Для снимков закрыть клиент и запустить `/usr/bin/yanjaro --capture-ui "$HOME/Pictures/yanjaro-rc2-review"`. Необходимы новые реальные изображения плеера, сгруппированных станций и поиска сущностей. Системную карточку фотографировать отдельно в оболочке, предварительно скрыв частные уведомления. SYNTHETIC снимки не заменяют их. `acceptance.json` содержит только числовые счётчики; для трёх партий нужен `wave_distinct_batches_played_max >= 3` плюс ручное подтверждение звука.
