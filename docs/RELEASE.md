## Сборка без изменения системного Python

```sh
./scripts/build-native.sh
```

Нужны инструменты `base-devel`, Python и зависимости из `packaging/PKGBUILD`. Скрипт **не** вызывает sudo/pacman/pip и не устанавливает их. Он создаёт архив исходников из белого списка, фиксирует SHA-256, генерирует `.SRCINFO` именно через `makepkg --printsrcinfo`, выполняет makepkg и сохраняет `dist/native/SHA256SUMS`. `SOURCE_DATE_EPOCH` можно указать явно. Сеть нужна только для получения указанного официального SDK wheel при сборке; при запуске установки зависимостей нет.

Нативный пакет хранит код в `/usr/lib/yanjaro`, команду в `/usr/bin/yanjaro`, desktop-файл в `/usr/share/applications/yanjaro.desktop` и SVG-иконку в hicolor. Запуск не зависит от рабочего каталога. PySide6, libmpv и python-mpv — зависимости pacman. SDK yandex-music 3.2.0 включён отдельным неизменённым модулем из официального wheel с SHA-256 и лицензией: в локальном Manjaro Stable его пакета нет. AUR-зависимости в этом рецепте отсутствуют; наличия `python-yandex-music` в AUR не заявляем.

До ручной установки кандидата системные PySide6 и python-mpv отсутствовали. Для проверки **содержимого артефакта** допустимо отдельно выполнить `YANJARO_SOURCE_CACHE=/tmp/yanjaro-wheels ./scripts/build-native.sh --nodeps --nocheck`. Это не проверка разрешения зависимостей, не чистая сборка и не доказательство установки/работы через pacman. Полные тесты выполняются в `.venv`; эти результаты указываются отдельно.

## Установка, запуск, обновление, удаление

Следующие команды изменяют систему. Пользователь уже согласовал и выполнил установку кандидата `-2` на основной Manjaro. `-3` исправляет очистку каталога сборки; перед публичным выпуском всё равно нужна проверка в чистой Manjaro Stable VM:

```sh
sudo pacman -U ./yanjaro-0.2.0rc1-3-any.pkg.tar.zst
/usr/bin/yanjaro
```

Команда установит только доступные из настроенных репозиториев зависимости. Файл `.pkg.tar.zst` не является автономным установщиком. Повторный запуск должен активировать существующее окно; сворачивание не останавливает музыку; закрытие завершает плеер. В GNOME расширения не нужны.

Для обновления закрыть приложение и установить проверенный новый пакет той же командой `pacman -U`. Для удаления: `sudo pacman -Rns yanjaro`, предварительно проверить предлагаемый pacman список. Токен не сохраняется, вход потребуется заново. Пользовательские базы и загрузки клиент не создаёт; локальный IPC использует `$XDG_RUNTIME_DIR`, будущие настройки/кэш должны использовать XDG, а не `/usr`.

Снимки **реального аккаунта** можно получить явным запуском:

```sh
/usr/bin/yanjaro --capture-ui "$HOME/Pictures/yanjaro-review"
```

Сначала закрыть уже запущенный клиент. Войти, запустить трек, открыть «Мне нравится», результаты поиска и «Станции». Снимок каждого непустого экрана сохраняется один раз, только после входа при загруженном треке; код входа исключён. Проверить снимки перед публичным использованием. Обычный запуск снимков не делает. В `acceptance.json` находятся только числовые счётчики полученных партий и партий, из которых начато воспроизведение; для границы партий нужен `wave_distinct_batches_played_max >= 2` вместе с ручным подтверждением звука.

## Обязательные проверки перед публикацией

- Собрать тем же PKGBUILD в чистой Manjaro Stable VM и чистом Arch chroot с проверкой зависимостей и `check()`; запустить namcap.
- Установить пакет через pacman в VM; проверить меню, иконку окна/панели и `/usr/bin/yanjaro` из другого каталога.
- Вход → любимое → поиск → полный звук → пауза → перемотка → громкость/mute → очередь и навигация.
- Станция: дождаться автоматического перехода хотя бы через одну границу API-партии. Тест с синтетическим SDK не заменяет эту проверку.
- Проверить отсутствие сети, ошибку продолжения и ручной повтор; повторный запуск, сворачивание, закрытие; обновление пакета поверх предыдущего кандидата.
- Проверить `org.freedesktop.secrets` после установки. Сохранение токена не реализовано, доступ к хранилищу не обещан.
- Сделать реальные снимки любимого/поиска/станций с выбранным или играющим треком. Снимки `tests/render_ui.py` помечены SYNTHETIC и не являются материалами живого аккаунта.
- Получить отдельное согласование публичного выпуска, сформировать общедоступный неизменяемый source URL с SHA-256; пересоздать `.SRCINFO` и пересобрать пакет. Текущий рецепт использует реальный локальный архив, поэтому для AUR пока не самодостаточен.
- Проверить свободу `yanjaro` непосредственно через AUR RPC. Создание/настройка аккаунта, подпись, отправка рецепта и Release — отдельное согласованное действие.
- **После** публикации в AUR и обновления метаданных Pamac проверить запросы `yanjaro`, `yandex music`, `яндекс музыка`. Desktop Keywords помогают искать уже установленное приложение; до публикации это не проверка каталога Pamac.

AppStream пока не создавался: для первого локального пакета он необязателен. MPRIS/медиаклавиш в исходной версии не было: отдельный следующий небольшой шаг — интерфейс `org.mpris.MediaPlayer2` поверх команд и событий текущего Player, с отдельной проверкой D-Bus и клавиш. Офлайн, синхронизация, lossless и ремонт истории в этот этап не включены.
