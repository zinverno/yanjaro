Причина: Docker socket `/var/run/docker.sock` недоступен агенту (permission denied); mkarchroot/arch-nspawn/podman/proot отсутствуют. bwrap user namespace доступен, но существующие host-overlay root не являются чистой ОС, а запрет socket bind мешает GPG/DBus. Повторять запрещённые действия или подменять dependencies системной venv не стали.

Подготовлен `scripts/check-clean.sh arch|manjaro`: официальный образ фиксируется RepoDigest, Manjaro обязан сообщить stable; исходный snapshot/recipe проверяются makepkg с контрольными суммами. Все зависимости ставятся pacman внутри контейнера из его собственных репозиториев. Полный build/check от обычного пользователя, без skip/nodeps/nocheck. Исходное дерево удаляется перед запуском установленного `/usr/bin/yanjaro` через harness; реальны QML/SVG/libmpv/IPC, отдельная тестовая D-Bus, только audio sink=null и автоматическое закрытие задаёт harness. Затем точный прежний rc2-2→новый пакет, проверка синтетической настройки и удаление. Домашняя папка, /usr, bus/keyring и аудиоустройства хоста не монтируются. Скрипт не подменяет результат: PASS пишется только после соответствующего действия; при ошибке завершается ненулевым кодом. Синтаксис проверен, фактический прогон контейнеров пока NOT RUN.

Команды владельцу, если Docker уже доступен (устанавливать/перенастраивать ОС в этом задании не требуется):

### Получение исходников и границы CI

`.github/workflows/clean-distros.yml` запускает две независимые matrix-задачи (`fail-fast: false`) на стандартном `ubuntu-24.04`. В каждой — отдельный Docker root, `pacman -Syu` и зависимости из собственных репозиториев. Manjaro дополнительно проверяет `ID=manjaro` и ветку `stable`. Образы разрешаются в RepoDigest перед запуском. Нет host `/usr`, `.venv`, домашнего каталога, аудиоустройств, session bus или Docker socket внутри тестового контейнера. Единственный переданный environment marker — разрешение одноразового тестового root; OAuth, реальный аккаунт, пользовательские базы и ключи не передаются. Checkout имеет только `contents: read`, credentials не сохраняются и в контейнер не попадают.

Свежий checkout не использует `dist/` разработчика. `scripts/prepare-clean.py` экспортирует полные закреплённые Git-коммиты из `packaging/clean-inputs.json`; внутри каждого дистрибутива исходный `prepare-native.py` создаёт архив с фиксированным SOURCE_DATE_EPOCH. Затем проверяются SHA-256, полный `makepkg --force --cleanbuild --noconfirm`, все тесты `check()`, desktop validation и соответствие сгенерированной `.SRCINFO`. Флаги отключения зависимостей, тестов или проверки целостности не используются.

- Кандидат rc2-3: commit `6e7af545e5da1a5bdca42a4ed512ca38d6fdcaf9`, epoch `1791433523`, исходный SHA-256 `18e037b5c29747ebb1bcf8b8045a367b69e20ca60540a6557299ffb9e383707c`. Архив, PKGBUILD и `.SRCINFO` совпадают с `packaging/candidate-rc2-3.json` и замороженным рецептом. Прежний архив не заменён содержимым текущего HEAD.
- Предыдущая версия для обновления: commit `fea11e61542a04cc139a42b5749e692d637a6509`, epoch `1791360000`, исходный SHA-256 `ce12d8c223012edd994c7df4fb8c95fc76ea4fc93ddb1b3b86e2ec097e8cb183`. Это явно обозначенная пересборка rc2-2; её документация содержит последующий отчёт. Это **не** исторический source с SHA `4233db47…` и **не** бинарник `7ba013af…`. Отдельно локально все 54 файла приложения из этого commit побайтно сверены с историческим rc2-2. Старые архивы/бинарники не перезаписывались.

`check-package.py` проверяет полный набор и байты ресурсов приложения, версию, launcher, лицензии, зависимости и исключение приватных файлов. Перед запуском удаляются оба распакованных дерева исходников; приложение вызывается через установленный `/usr/bin/yanjaro` из `/tmp`, без PYTHONPATH/QML/venv разработчика. Проверяется rc2-2 → rc2-3, сохранение синтетической настройки, новая установка rc2-3 после удаления, затем окончательное удаление без удаления тестовой пользовательской настройки. Проверка `pacman -Qkk` остаётся обязательной.

Это headless-проверка: настоящий Qt/QML/SVG/libmpv, отдельная тестовая D-Bus, `QT_QPA_PLATFORM=offscreen`, `ao=null` и автоматическое закрытие через harness.
