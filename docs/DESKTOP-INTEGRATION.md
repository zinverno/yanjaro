# Вход и системное управление

«Запомнить аккаунт на этом устройстве» включено по умолчанию. Yanjaro использует только постоянную коллекцию `default` системного Secret Service, через SecretStorage 3.5+. Запись имеет атрибуты `application=yanjaro`, `purpose=active-account-v1`. Пароль Яндекса не запрашивается, токен не переносится в JSON, настройки, логи или пакет. Альтернативных plaintext-backend нет. На KDE необходим доступный провайдер Secret Service (например, ksecretd); на GNOME обычно это GNOME Keyring. Наличие провайдера и разблокировку проверяют в настоящем пользовательском сеансе.

На старте чтение и проверка аккаунта идут в worker. Заблокированное хранилище не открывает диалог само: «Повторить доступ» позволяет запросить разблокировку. Отмена, отсутствие постоянной коллекции и недоступный сервис отображаются отдельно. Можно снять «Запомнить» и войти только на сеанс. После входа отказ записи показывается явно; повтор сохранения доступен в настройках аккаунта. Автовоспроизведения после восстановления входа нет.

Сбой сети не удаляет запись. HTTP 401 и 403 различаются до обработки SDK: только 401 подтверждает недействительный вход, 403 означает ограничение доступа. Даже недействительная запись удаляется явным действием. Refresh flow не добавлен; срок действия не выдумывается, действительность проверяет сервер. Выход блокирует автоматическое восстановление, очищает текущий сеанс и удаляет только запись Yanjaro. При отказе удаления интерфейс предлагает повтор. Обновление пакета не трогает Secret Service и пользовательские XDG-каталоги.

MPRIS: `org.mpris.MediaPlayer2.yanjaro`, `/org/mpris/MediaPlayer2`, desktop entry `yanjaro`. Все команды идут в PlaybackController; Position/Seeked имеют signed int64 микросекунды, metadata не содержит аудиоссылок. Поддержки произвольных URI и удалённого TrackList нет. В радио LoopStatus=None и Shuffle=False, изменение этих режимов возвращает NotSupported; предпочтения конечной очереди сохранены. Next/Previous сохраняют паузу и Stop, выбор строки явно запускает музыку.

Оценён PySide6.QtDBus 6.11.2: прямое `QDBusArgument << int` выбрало uint16 (`q`) даже для int/float/bool; большие значения вызвали overflow. Для точных типов используется уже необходимый SecretStorage транспорт Jeepney с явными сигнатурами и Qt QSocketNotifier. Это тот же Qt event loop, без GLib/второго GUI-стека. Сообщения проверяются сериализацией/десериализацией, а не только Python-словарями.

В sandbox агента запуск тестового `dbus-run-session` отклонён: `Failed to bind socket: Operation not permitted`. Это BLOCKED для настоящей D-Bus, а не вывод о доступности на ноутбуке. Отдельная скрытая сессия не используется приложением. В обычном терминале после согласованной установки:

```sh
/usr/bin/yanjaro
playerctl --list-all
playerctl --player=yanjaro status
playerctl --player=yanjaro metadata
playerctl --player=yanjaro play-pause
playerctl --player=yanjaro next
playerctl --player=yanjaro previous
```

playerctl нужен только для диагностики, не runtime-зависимость. Оболочка выбирает вид и расположение карточки. Проверить название/обложку, паузу и переходы, свёрнутое окно, отсутствие второй карточки при повторном запуске. Закрытие завершает приложение, сворачивание сохраняет музыку.

Живая приёмка хранения: вход → закрыть → запуск из меню без браузера; выход → запуск без входа; обновление пакета; новый сеанс ОС при возможности. Ошибки хранилища проверять на отдельной тестовой записи, не блокируя/удаляя личную коллекцию. Сбой сети и возврат проверять только в разрешённой среде. Не прикладывать токены и дампы хранилища к отчёту.
