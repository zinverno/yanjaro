## Причина и изменения

`canPrevious` и команда Previous учитывали только историю уже начатого воспроизведения. При первом запуске строки №45 история не содержала предыдущего перехода, хотя все ID любимого уже находились в очереди. Теперь реальная история имеет приоритет; после её начала выбирается предыдущая доступная позиция полной очереди. Добавляется запись в начало навигационной истории, поэтому повторный Previous продолжает идти назад, а Next возвращается вперёд. Очередь не обрезается и не дополняется копиями треков; подгрузка метаданных остаётся ленивой.

Дополнительные тесты обнаружили три гонки в исходном патче: быстрый Previous по истории выбирал старый курсор; CanGoNext мог выключаться на загружаемом последнем элементе очереди с доступным будущим в истории; прямой выбор из очереди мог наследовать старый history_target и терять новую запись истории. Общий расчёт позиции теперь учитывает выбранную, но ещё загружаемую запись. Прямой выбор и выход вперёд за историю очищают старую цель. Уже существующие generation/revision и отмена запросов продолжают отбрасывать позднее аудио.

Radio не получает новый Previous. Пауза сохраняется при командах Previous/Next, Stop не запускает звук. QML и MPRIS используют те же canPrevious/canNext общего контроллера; отдельные флаги/кнопки не добавлены. Repeat/shuffle и API feedback не переписаны.

## Короткая ручная проверка после согласования установки

1. В «Мне нравится» выбрать песню примерно из середины. Previous должен быть доступен: два нажатия ведут назад на две позиции, Next дважды возвращает к выбранной песне. Очередь не теряет начало и не получает дубли.
2. Сделать несколько быстрых Previous/Next. Убедиться, что звучит последний выбранный трек, без внезапного возврата старого. На паузе Previous/Next сохраняют паузу.
3. Повторить Previous/Next из настоящей системной MPRIS-карточки. В «Моей волне» Previous остаётся недоступен; полную прошлую приёмку радио/поиска повторять не требуется.

Без разрешения не устанавливать rc4 на основную систему, не выполнять merge/auto-merge, теги, Release или AUR. Проверенный rc3-1 сохраняется с прежним исходником, пакетом и manifest. Лицензия, публичность, зависимости и остальные функции не меняются.
