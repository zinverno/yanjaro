# Предложение: локальный пилот ритмического сходства полной аранжировки

**Только предложение, NOT RUN.** Без обучения и новых загрузок. Цель — проверить,
соответствует ли v2 uniform человеческому сравнению ритма, когда одновременно
звучат несколько инструментов. Это меньший следующий шаг, чем новый learned model.

Источник — уже имеющиеся десять CC0 композиций/игровых loops трёх авторских групп.
Файлы занимают **56 973 324 bytes (54,33 MiB)**, суммарная длительность
**1084,295 с (18,07 мин)**. Они уже локальны; это не бюджет новой передачи.
Примеры первичных страниц с CC0: [Jazz — Spring Spring](https://opengameart.org/content/jazz-1),
[Funked Up — Joth](https://opengameart.org/content/funked-up),
[Boss Battle Music — SubspaceAudio](https://opengameart.org/content/boss-battle-music).
В текущем этапе проверены страницы и прежние hash-bound license evidence;
аудиоссылки не скачивались. Полный список source URLs/hashes/attributions находится
в `validation/rhythm-v2-diagnostics-v1/local-waveforms.json`.

Сохранённое разрешение ограничено локальной диагностикой: training=false,
remote=false. Новый listening protocol и участие рецензентов следует согласовать
отдельно. Предлагается прослушивание на локальной машине владельца, без публикации
клипов, внешней платформы или передачи файлов. CC0 и разрешение на конкретный
эксперимент — разные проверки.

1. Два человека независимо размечают BPM, meter, downbeat и границы полных тактов
   внутри уже разрешённых 15-секундных окон. До algorithm scoring фиксируют hashes,
   bar-phase uncertainty и причины исключений. Допускаются 4/4, 40…260 BPM и
   uncertainty ≤1/16 beat на всём окне. Нет достоверной фазы — abstain, без подбора
   origin по MIDI, v1/v2 distance или предпочтительному результату.
2. Составить **24 distinct triplets** по metadata и человеческой rhythm-разметке,
   не по признакам. Все три оригинала в сравнении различны; авторские группы
   распределить между anchor/A/B, порядок A/B сбалансировать фиксированным seed.
   Сравнивать близкие tempi (предлагаемый предел 10%, без time stretching), включая
   контраст «похожий пульс, разные рисунки». Если имеющийся pool не позволяет
   получить 24 допустимых сравнения, остановиться с фактическим N; не ослаблять
   условия и не докачивать новые записи автоматически. При N<20 — только feasibility.
3. Два слепых рецензента, не видящие авторов, genre и расстояний модели, отвечают:
   «У какого фрагмента ритмический рисунок ближе к anchor, независимо от тембра и
   личной симпатии?» Варианты A/B/одинаково близки/ни один/не уверен/пропустить.
   Выход добровольный, без PII и учётных записей. Разногласия не разрешаются с
   помощью модели. Сохранить все ответы, agreement, skips и причины abstention.
4. До открытия модельных результатов заморозить labels. Сравнить v1 uniform и
   v2 uniform один раз: для каждого окна mean squared distance по всем парам
   допущенных полных тактов; для каждого triplet показать margins, верно/ошибка/ничья,
   flips и denominators. Primary accuracy только на согласованных A/B labels,
   ничья модели даёт 0,5; нейтральные/неуверенные ответы отдельно. Публиковать также
   результаты каждого reviewer и coverage отказов extractor, не только agreed subset.
5. Считать это диагностикой полных аранжировок на коротких окнах, **не** качеством
   целой песни, не независимым song-level test и не доказанным превосходством.
   Общие оригиналы связывают triplets; всего три авторские группы. Отчёт по
   оригиналам/компонентам и paired disagreement важнее формального p-value.
   Если нужны выводы о целой композиции, отдельно согласовать несколько секций
   каждой записи и больше независимых авторов: нынешние 15 с этого не проверяют.

Предлагаемый реальный бюджет следующего пилота:

| Ресурс | Верхняя граница / оценка |
|---|---|
| Новая загрузка / публикация аудио | 0 bytes / 0 bytes |
| GPU, remote training, paid API | Не нужны, денежный расход 0 |
| Локальный CPU | ≤600 CPU s, два потока, wall ≤10 мин на расчёт |
| Память / новые численные артефакты | RSS ≤1 GiB / ≤2 MiB |
| Ручная phase-разметка | 20–30 человеко-минут, оценка |
| Blind judgments | 24×2×60–90 с = 48–72 человеко-минут, оценка |
| Инструктаж/проверка согласия | 15 человеко-минут, оценка |
| Полный труд | Около 83–117 человеко-минут; бесплатно только при добровольном участии |

Основание CPU-резерва: текущие waveform diagnostics 150 с аудио заняли 10,27 CPU s
и 331,70 MiB RSS; повторное извлечение по отдельным тактам и v1 потребуют больше.
600 s и 1 GiB — предлагаемые пределы, а не уже измеренная стоимость будущего опыта.
Использовать готовое локальное окружение; если потребуются Python/packages,
учитывать их ненулевой инфраструктурный трафик отдельно.

Для следующего **обучения** этого pool недостаточно: нужны отдельное разрешение
на training, независимые rhythm labels, больше авторских групп, disjoint
train/validation/new-test по источникам и авторам, зафиксированные phase/coverage
checks, v2 feature schema и неизменяемый model receipt. Первым должен пройти
необученный extractor и его соответствие целевой задаче; learned weights не
исправят отсутствие нужной информации в представлении.
