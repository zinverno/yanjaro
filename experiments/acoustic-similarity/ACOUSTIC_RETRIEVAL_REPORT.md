### UNKNOWN и покрытие

У пропущенного блока **distance=null**, с ID источника и причиной. Никакого
численного штрафа 0, 0.5 или 1. Для каждой пары сохранены расстояния по общим
доступным блокам, их маска, весовое покрытие и условное расстояние на этом покрытии.
При отсутствии любых общих признаков — ABSTAIN (на этих десяти такого нет).

Общий порядок сначала предпочитает большее покрытие; при равном покрытии разные
маски упорядочивает по заранее фиксированному порядку блоков. Только внутри
**одинаковой маски** сравнивает D_common, затем ID при точном равенстве. Это
административная стратегия выдачи, не доказательство, что более полная пара
музыкально ближе. Далёкий полный кандидат может опередить близкого неполного.

Найдены два реальных пропуска:

- u01: H отсутствует — `NO_QUALIFYING_TEMPO_PEAK`;
- s04: P3, полоса 3000–8001 Hz — `NO_HISTOGRAM_MASS`. Это отсутствие пригодной
  гистограммы при фиксированном детекторе, не доказательство отсутствия инструмента.

Из 45 пар: 28 имеют покрытие 100%; восемь — 47/48=97.9167% без P3;
восемь — 36/48=75% без H; одна s04/u01 — 35/48=72.9167% без P3 и H.
Покрытие означает доступность, **не независимую точность** tempo или других признаков.

### Формула

[Полная frozen specification](ACOUSTIC_RETRIEVAL_SPEC.md) описывает маски,
целочисленные веса, нормализацию, ограничения и sensitivity policy.

- Rhythm: PI periodicity, normalized intervals и density; tempo H исключён.
- Tempo: только PI hypothesis histogram. Старые DSP BPM/rhythm/overall не входят.
- Timbre: 85 прежних DSP-координат; energy/dynamics: десять прежних координат.
- Для гистограмм Hellinger: `sqrt(sum((sqrt(p)-sqrt(q))²)/2)`.
- Для density: mean absolute difference.
- DSP сохраняет прежние физические масштабы и clip [-3,3]; расстояние каждого
  аспекта — `RMS((raw_a-raw_b)/6)`, то есть bounded dimensionless distance [0,1].
  Нет оценки средних/дисперсий или масштабов по этим десяти записям.

При полном покрытии `D=(R+H+T+E)/4`. Каждый аспект имеет бюджет 1/4.
При неполном покрытии суммируются только общие атомарные вклады и делятся на
сумму их весов. `conditional_score=100*(1-D_common)`. Для одной отсутствующей
полосы rhythm тоже усредняется только по доступным частям, с сохранением их весов.

При полном покрытии один аспект меняет D максимум на 0.25. При покрытии 75%
один целиком доступный аспект может менять D_common на 1/3: это явно отражено в
политике, а не скрытое равенство разных scores. **Scores разных масок нельзя
сравнивать напрямую.** H учитывается арифметически один раз, но абсолютные лаги
и плотность тоже чувствительны к скорости: статистическая независимость R/H не
заявляется. Тембровые/энергетические temporal curves также не фазоинвариантны.

Для 28 пар с полным покрытием средние R/H/T/E:
**0.223659 / 0.774420 / 0.009459 / 0.013673**.

### Контрольные сигналы и исправленные ошибки

Synthetic tests проверяют UNKNOWN query/candidate/both, partial/no-common,
неизменность известного PI-расстояния, разные BPM при одинаковой структуре
интервалов, разные рисунки при заданных 120 BPM, изоляцию T/E, aspect bounds,
source aliases, порядок JSON keys, deterministic ordering и повтор извлечения.

При известных одинаковых атаках смена carrier 220→2200 Hz дала:
R=0.018896, H=0, T=0.021797, E=0.000425. Небольшое изменение R показывает
межаспектную чувствительность spectral onset detector; это не идеальная
декомпозиция музыкальных факторов. Уменьшение gain 1→0.2: R≈0, H=0,
T≈0.000015, E=0.022137. Все synthetic результаты — механика, не relevance labels.

Действительно исправлено: численная подстановка вместо missing distance;
скрытое сравнение неполных и полных scores; отсутствие явного покрытия.
Добавлен частичный поиск по T/E при отсутствии PI. Известные PI-пары с полными
признаками сохраняют прежнюю формулу. Арифметический двойной учёт H в общей
схеме предотвращён. Музыкальная неоднозначность BPM и instrument confusion
не исправлены этой политикой.

## 3. Неизвестное акустическое качество

Human acoustic quality, независимая accuracy, Recall@K — **NOT RUN**.
Рецензенты не приглашались, правильные ответы не назначались. Существующий
[RHYTHM_PI_REVIEW.md](RHYTHM_PI_REVIEW.md) сохранён без изменений.

Непроверены: правильность найденных соседей, новые композиции/авторы,
обобщение между окнами и частями песни, устойчивость к мастерингу/стереосведению,
полнота событий и независимая правильность tempo. Этот набор уже раскрыт:
любые следующие решения по нему будут exploratory, не held-out evidence.

## 4. Данные, нужные до реального обучения общей модели

Нужен отдельно разрешённый корпус полноценных аранжировок с заранее выбранными
окнами, независимыми artist/recording groups и split до анализа. Нужны человеческие
акустические сравнения по rhythm/tempo/timbre/energy и общему сходству, варианты
«оба/ни один/не уверен», несколько независимых reviewers и протокол разногласий.
Предпочтения, жанры, популярность и вычисленные scores не могут стать truth labels.

Нужны контрастные случаи: близкий ритм при разном тембре, близкий тембр при разной
энергии, сходные patterns при разных темпах, неполные признаки/неуверенный tempo.
Для Recall@K требуется независимо размеченный релевантный набор в фиксированном
candidate pool; одних 12 информативных triplets недостаточно. Калибровку масштабов
и будущие веса выбирать только на train/validation, после чего фиксировать модель
и оценивать на независимом test. Disclosed drummer6/drummer8 для этого не подходят.
Новое обучение, сбор аудио и recruitment здесь не запускались.

## Воспроизведение, ресурсы и provenance

Все десять originals/evidence проверены до decode и после извлечения. Использованы
только прежние 15 секунд: девять с 30 s, o03 с 3.6244671201814054 s. Нативные
sample bounds сохранены. Новая композиция использует неизменённые проверенные
cached coordinates; их текущая повторная экстракция оказалась точно идентичной.

Основной bounded study, включая 12 synthetic tests, все повторные извлечения,
три варианта рейтинга и 19 sensitivity-сценариев:
**27.530650 CPU s** включая imports; **24.828073 wall s** после imports;
**438.871094 MiB peak RSS**, два вычислительных потока. Hard limits: 540 CPU s,
1 GiB virtual memory. Численные артефакты **932774 байт <2 MiB**.

Новых аудиозагрузок **0 байт**, network внутри study **0**, GPU/paid API/remote
training нет. Новое отдельное Python 3.12.13 окружение установлено из прежнего
requirements.lock; это ненулевой инфраструктурный трафик, как и Git/CI. Он не
объявляется аудиотрафиком или нулевыми сетевыми затратами. Runtime: numpy 2.2.6,
scipy 1.15.3, librosa 0.11.0, soundfile 0.13.1, numba 0.61.2.
Process receipts относятся к основному study; подготовка окружения, предварительные
локальные tests и CI имеют отдельный overhead. Реальное исследование находится
далеко ниже разрешённых 600 CPU s.

```sh
# Только уже существующие локальные manifest/index, без автоматического скачивания.
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 NUMBA_NUM_THREADS=2 PYTHONPATH=. \
  python scripts/acoustic_retrieval_study.py --manifest "$LOCAL_APPROVED_MANIFEST" \
  --dsp-index "$LOCAL_DSP_INDEX" --out /tmp/acoustic-retrieval-new

# Реальный поиск по сохранённому индексу, без доступа к аудио:
OPENBLAS_NUM_THREADS=2 PYTHONPATH=. python -m acoustic_similarity.acoustic_retrieval \
  --index validation/acoustic-retrieval-v1/index.json --query u01
```
