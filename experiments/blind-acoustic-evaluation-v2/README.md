# Blind Acoustic Evaluation v2

Отдельный локальный эксперимент поверх неизменного PR #11
(`a9fe148cc9b81fcfb76d55ea11d18b701bbd0e84`).
[Протокол](PROTOCOL.md) фиксирует дизайн до ответов.
**Реальные 12–16 новых записей ещё не предоставлены; индексация, конкретные
сравнения и человеческая оценка — NOT RUN.** Это подготовка инструмента, не результат
эксперимента. Прежнее неслепое впечатление о «Логике»/Blurry не входит в ответы.

## Что подготовлено

- Acoustic Retrieval v1, исправленный PI (`pi_coverage_v2`) и tempo-only на той же
  гистограмме tempo. Веса, формулы и старые файлы не меняются.
- Детерминированный выбор 6 расхождений + 4 контролей согласия + 2 обратных повтора:
  всего 12 предъявлений, 10 уникальных случаев. Не хватает группы — BLOCKED.
- Две автономные страницы с разным порядком и противоположным A/B, без названий,
  score, алгоритмов и предсказаний. A/B/tie/neither/uncertain, пропуск, необязательные
  аспект и уверенность; JSON/CSV, восстановление, удаление и защита от конфликта вкладок.
- Закрытие обеих сессий перед анализом; отчёт JSON и Markdown с явными знаменателями,
  группами, ни одним/ничьей, разногласиями слушателей и отдельной проверкой повторов.

Из PR #11 переиспользуются шаблон страницы, приватная запись файлов, JSON/CSV и
валидационные примитивы. `app.js` — отдельная копия его UI; единственное изменение
логики — длина сессии берётся из пакета вместо фиксированных 14. Старый `frozen.json`,
страницы, данные и код PR #11 не изменяются. Все зависимости уже есть в прежнем lock;
новых зависимостей, веб-сервера и endpoint для ответов нет.

## Инструкция владельцу

1. Подготовьте новый checkout ветки `experiment/blind-acoustic-evaluation-v2`.
   Не переключайте и не изменяйте существующие экспериментальные checkout/ветки.
   Установите **Python 3.12.13** и прежние locked-зависимости в отдельное окружение.
   Установка пакетов требует обычного доступа к PyPI; сам эксперимент работает offline.

   ```sh
   git clone --branch experiment/blind-acoustic-evaluation-v2 https://github.com/zinverno/yanjaro.git yanjaro-blind-v2
   cd yanjaro-blind-v2
   export EVAL_PRIVATE="$HOME/.local/share/yanjaro-blind-v2"
   umask 077
   mkdir -p "$EVAL_PRIVATE"
   python3.12 -m venv "$EVAL_PRIVATE/venv"
   export EVAL_PY="$EVAL_PRIVATE/venv/bin/python"
   "$EVAL_PY" -m pip install --require-hashes --only-binary=:all: -r experiments/acoustic-similarity/requirements.lock
   "$EVAL_PY" experiments/blind-acoustic-evaluation-v2/evaluate.py init --plan "$EVAL_PRIVATE/plan.json"
   ```

2. **До любых рейтингов** заполните созданный `plan.json` (он намеренно не проходит
   проверку с пустыми полями). Оставьте 12–16 строк новых разрешённых композиций.
   `previous_yandex_track_ids` — ровно четыре прежних ID; `excluded_recording_groups` —
   их группы записей, включая известные альтернативные версии/ID той же записи.
   Для каждой новой строки укажите уникальный `id` (например `t01`), реальный Yandex ID
   или `null` для другого разрешённого источника, абсолютный `path`, SHA-256 файла,
   `artist_ids`, `recording_group`, `start` и фиксированные `seconds: 15`, `split: test`.
   Сопоставьте записи вручную и установите `novelty_reviewed: true` только после проверки.
   Десять прежних pilot-записей дополнительно исключаются по хешам и группам.

   Для `rights` заполните основание/лицензию, источник, атрибуцию, дату проверки,
   разрешённый scope и путь/хеш локального документа-доказательства; подтвердите
   `reviewed`, `acquisition`, `analysis`, `local_feature_storage`, `private_listening`
   только если соответствующее использование действительно разрешено. `private_listening`
   должно покрывать предполагаемых слушателей. Подписка или технический доступ не
   заменяют эти основания. `sha256sum /absolute/path` вычислит хеш; исходники не надо
   помещать в Git или пересылать агенту. Имена/аккаунты слушателей не собираются.

   Используйте уже разрешённые локальные файлы. Этот этап не включает сбор потока
   Яндекса, обход DRM, выгрузку каталога или повторное использование старого согласия
   Personal Index. Если таких файлов нет, остановитесь: приобретение/захват требует
   отдельного решения владельца и проверки допустимого использования.

3. Проверьте декларации и хеши. Эта команда ничего не декодирует и не индексирует:

   ```sh
   "$EVAL_PY" experiments/blind-acoustic-evaluation-v2/evaluate.py preflight --plan "$EVAL_PRIVATE/plan.json"
   ```

4. Когда готовы **локально разрешить индексацию именно этого набора**, запустите в
   своём интерактивном терминале:

   ```sh
   "$EVAL_PY" experiments/blind-acoustic-evaluation-v2/evaluate.py prepare --plan "$EVAL_PRIVATE/plan.json" --out "$EVAL_PRIVATE/run-1"
   ```

   Команда покажет хеш плана и попросит напечатать `INDEX <12 символов хеша>`.
   Только после этого начнётся извлечение признаков. Флага `--yes` нет. Выходная
   папка должна быть новой и вне Git. Нельзя передать pipe с подтверждением.
   Ошибка сохраняет уже созданные диагностические файлы; не удаляйте и не
   перезаписывайте запуск. Если извлечение/квоты не прошли — слушание не начинать,
   сначала разберите техническую причину без подбора выгодных параметров/песен.

5. При успехе сохраните отдельно `organizer/seal.txt` **до первого ответа**.
   Убедитесь, что `organizer/freeze.json` существует: это завершённая фиксация.
   В `organizer/` лежат план, согласие, версии, индекс, рейтинги, выбор и ключи;
   в `listeners/` — только страницы с непрозрачными ID и локальным аудио;
   `responses/` изначально пуст. Не публикуйте ничего из `run-1`, включая HTML:
   страницы содержат аудио. Не запускайте HTTP-сервер над этой папкой.

   Если владелец сам слушатель, не открывайте `index.json`, `predictions.json`,
   `packages.json` и план сопоставления во время теста. Желателен отдельный организатор.
   Узнавание песни на слух возможно; это слепота к алгоритмам и их результатам.

6. Каждый слушатель независимо открывает только свою страницу:

   ```sh
   xdg-open "$EVAL_PRIVATE/run-1/listeners/listener-1.html"
   # Второму слушателю предназначен listener-2.html.
   ```

   Первое открытие: проверьте звук X/A/B, сохранение/восстановление, громкость и
   устройство. При проблемах воспроизведения остановитесь; не отвечайте за неслышный
   фрагмент. Можно пропускать, слушать повторно и делать перерывы. Не обсуждайте
   ответы, не открывайте две вкладки одной сессии. Экспортируйте JSON (или CSV) в
   `responses/`. Выберите один финальный экспорт на слушателя; не передавайте
   одновременно JSON и CSV одной сессии. До завершения обоих не раскрывайте рейтинги.

7. После завершения скопируйте `organizer/closeout.template.json` в отдельный
   `closeout.json`; для **каждого** слота замените `pending` на `completed` или
   `withdrawn`, сохранив seal. Для единственного слушателя второй слот — `withdrawn`.
   `completed` разрешает явные пропуски; они считаются отдельно. Удалите отозванные
   экспорты и не передавайте их анализатору. Затем:

   ```sh
   "$EVAL_PY" experiments/blind-acoustic-evaluation-v2/evaluate.py analyze \
     --run "$EVAL_PRIVATE/run-1" --closeout "$EVAL_PRIVATE/closeout.json" \
     --out "$EVAL_PRIVATE/report-1" \
     "$EVAL_PRIVATE/run-1/responses/listener-1.json" \
     "$EVAL_PRIVATE/run-1/responses/listener-2.json"
   ```

   Укажите фактические имена файлов; при withdrawn передайте только оставшийся
   экспорт. Получатся `report.json` и `report.md`. Сверьте seal с сохранённой копией.
   Хеш связывает артефакты и выявляет случайное изменение; это не цифровая подпись
   против организатора, который может переписать одновременно артефакты и seal.

Небольшая выбранная выборка даёт описательное согласие, не population accuracy.
После использования ответов для изменения модели подтвердить новую модель можно
только новым набором и новыми ответами. Никакое обучение здесь не предусмотрено.

## Технические проверки

```sh
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 NUMBA_NUM_THREADS=2 \
  "$EVAL_PY" -m unittest discover -s experiments/blind-acoustic-evaluation-v2 -p 'test_*.py' -v
node experiments/blind-acoustic-evaluation-v2/test_ui.cjs
```

Тесты используют только синтетические waveform/descriptor fixtures и ответы в
памяти; они не являются человеческими оценками. См. [VALIDATION.md](VALIDATION.md).
