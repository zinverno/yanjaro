# Yanjaro Listening Study v0.1

Отдельное исследование выбора следующей песни: ритм/темп/динамика против жанра/инструментовки. Сейчас разрешены **только synthetic demo и подготовка реального пилота**. Слушателей и реальной музыки в результатах нет.

Эксперимент не импортирует Yanjaro, Acoustic Lab или Yambda. Нет обучения, эмбеддингов, аккаунтов, загрузчика аудио, публичного сервиса или интеграции с плеером. Все команды выполняются из этой папки. Python 3.13; отдельное окружение:

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m listening_study demo work/demo-v01
```

Открой `work/demo-v01/demo-next.html` в браузере: это полноценная автономная страница со встроенными **синтетическими** WAV. `demo-similarity.html` показывает альтернативную формулировку. Аудио, HTML и ответы не добавляются в Git. Генератор создаёт 24 сигнала × 8 секунд, 8 заданий (6 A/B, 2 C/D), frozen manifest, явную scripted-review и 32 файла искусственных ответов. **Demo-теги вымышлены, они не являются музыкальной разметкой.**

Для локального HTTP-режима:

```sh
.venv/bin/python -m listening_study serve work/demo-v01/study.json --slot 0 --question next
# Открыть ровно http://127.0.0.1:8765; остановить Ctrl+C.
```

Сервер привязан только к `127.0.0.1`; настройки публичного bind нет. Перед новым участником оператор останавливает сервер и увеличивает `--slot` отдельно для каждого `--question`. Одновременно обслуживается одно назначение. Это локальный прототип для сопровождаемой сессии, не платформа удалённого набора.

Ответы существуют в памяти браузера; в конце участник добровольно скачивает JSON. Нет POST-приёмника, access-логов, cookies, localStorage, sessionStorage, внешних шрифтов или аналитики. Отказ очищает несохранённые ответы и источники audio. Ранее скачанный файл нужно удалить отдельно. Реальные ответы хранить только в приватной папке вне Git, не в CI/artifacts. Случайный UUID связывает ответы одной сессии; личности пользователя приложение не знает и повторное участие само не распознаёт.

```sh
.venv/bin/python -m listening_study analyze work/demo-v01/study.json \
  work/demo-v01/responses work/demo-v01/results.json --draws 2000 --seed 20261009
```

Файлы вывода создаются только по новым путям. Замена замороженного исследования, review или результата не выполняется. Перенос абсолютных путей локальных клипов требует нового manifest/hash; для воспроизведения сохранить рабочую папку и версию кода.

## Подготовка будущей разрешённой выборки

1. Прочитать [протокол и план пилота](PROTOCOL.md) и [источники/лицензии](SOURCES.md). Получить подтверждения для конкретных записей и способа показа; лицензия датасета не заменяет разрешения на аудио.
2. Сохранить официальный TSV локально и выбрать **до 60** ID вручную. Импорт не обращается к сети и не принимает пути к аудио из TSV:

   ```sh
   .venv/bin/python -m listening_study import-mtg /private/autotagging.tsv work/selected-tags.json \
     --revision cafd8e20c265ed84f1e61f1c875327971f43a62f --ids track_0000001 track_0000002
   ```

   ID здесь — примеры синтаксиса, не разрешённые записи. Revision должен соответствовать **вашему** TSV. Импорт сохраняет SHA-256 TSV и положительные жанровые/инструментальные теги. Пустая категория означает `unknown`; mood/theme не используется для подбора.
3. По [шаблону sample](examples/sample.template.json) составить manifest с 3–60 явно перечисленными файлами. Перенести выбранные `genre`/`instrument` и provenance импорта. Заполнить rights ledger с доказательством права на анализ, нарезку, выравнивание уровня, локальное прослушивание и отложенную атрибуцию при слепом показе. Недостаточные права → запись исключается. Шаблон намеренно не готов к запуску.
4. `prepare sample.json work/prepared-v01` проверяет права **всего** списка до декодирования. Читает только выбранные локальные файлы ≤100 MiB, mono/stereo 8–96 kHz, отрывки 8–30 с. Прямой libsndfile, без shell/сетевых декодеров. Для пилота выбрать одинаковые 15 с по заранее фиксированному правилу. Raw SHA, границы, gain, права, raw и rendered признаки сохраняются.
5. `screen work/prepared-v01/catalog.json work/review-v01.json` создаёт предварительные пары и незаполненные проверки. Проверяющие прослушивают кандидатов **до** ответов участников. Заполняют четыре флага и содержательную заметку; вручную добавляют `trials`, используя [demo-taskset](examples/demo-taskset.json) как образец структуры. `first` = A в primary/C в control, `second` = B/D. Это частный исследовательский файл.
6. Заморозить:

   ```sh
   .venv/bin/python -m listening_study freeze work/prepared-v01/catalog.json work/review-v01.json \
     work/pilot-v01.json --study-id pilot-v01 --seed 20261009 --phase pilot
   ```

   Хэш связывает стимулы, признаки, review, параметры и задания. Клипы проверяются по SHA-256 перед запуском и фиксируются в памяти сервера. Не использовать одну запись повторно в одной сессии; артисты внутри тройки должны различаться. Непроверенные/неоднозначные пары не проходят freeze.

## Файлы и проверки

- `audio.py`, `metadata.py`: явные признаки и локальный импорт положительных тегов.
- `design.py`: четыре условия, manual-review gate, заморозка и контрбалансировка.
- `server.py`, `portable.py`, `web/`: закрытый локальный показ и synthetic-only HTML.
- `analysis.py`: строгая анонимная схема, оценка и кластерные интервалы.
- [FORMAT.md](FORMAT.md): форматы и проверка анонимности.
- [VALIDATION.md](VALIDATION.md): PASS / FAIL / NOT RUN; границы доказательств.
- `tests/browser.cjs`: настоящее воспроизведение WAV, экспорт, отказ, desktop/mobile и HTTP. Нужен Playwright 1.63.0 + Chromium; `PLAYWRIGHT_MODULE` может указывать установленный модуль. CI устанавливает их только во временное окружение runner.

Модель/экстрактор не проверен на реальной музыке. Близкие числа — только способ подготовить кандидатов для ручной проверки, не доказательство слухового сходства.
