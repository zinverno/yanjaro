# Первый набор: 32 участника — план, не публичное размещение

Статус: подготовка. Новые материалы дополняют draft PR #9 от `3eacfc819deeeb507c25c286bed3deacc7ea204e`. Публичный сервис, аккаунт SurveyCircle и платные ресурсы не создавались. Реальные записи и ответы не загружались. Плеер, Release, AUR, Render, PR #6/#7 и Yambda не затрагиваются.

## Минимальная схема размещения

Один отдельный HTTPS-origin → reverse proxy → один процесс эксперимента на `127.0.0.1` → один приватный SQLite-файл. Интерфейс, API и разрешённые WAV обслуживаются с одного origin. Без CDN, внешних плееров, аналитики, аккаунтов слушателей, SSO или сторонней базы. SurveyCircle только направляет людей; ответы не передаются платформе. Своё имя/аккаунт исследователь вводит только в SurveyCircle, не в записи участников.

Предлагаемый ресурс: существующий **отдельный** Linux-host, если он есть, с отдельным непривилегированным пользователем, HTTPS-поддоменом и приватным зашифрованным диском. Никаких изменений существующего Yanjaro/Render. Если отдельного host нет, сначала выбрать провайдера/регион, проверить условия и стоимость и получить согласование; бесплатность не предполагается. Оценка нагрузки: 24 × 15 s × 16 kHz × 2 bytes ≈ 11.5 MB PCM на полный проход, около 0.37 GB на 32 прохода без повторов. Повторы и более высокая частота увеличат объём; это расчёт, не измеренный тариф.

`collect` остаётся **локальным preview**. Перед внешним запуском нужно завершить и проверить production HTTP-обвязку: [Python предупреждает, что http.server не предназначен для production](https://docs.python.org/3/library/http.server.html). Вариант production — перенести существующие маршруты на WSGI за поддерживаемым сервером и reverse proxy, сохранив `Collection` и формат API; затем повторить эти же acceptance-тесты через HTTPS. Это явный незакрытый инфраструктурный gate, не разрешение выставить preview-порт в интернет. Новые production-зависимости и конфигурация будут частью согласованного размещения.

Параметры предлагаемой обвязки для приёмки:

- Один инстанс; приватные `study.json`, config и clips read-only, SQLite writable только владельцу (0600 в каталоге 0700). База вне web-root и Git. Не размещать на ephemeral filesystem/serverless с локальным SQLite.
- Сертификат TLS, принудительный HTTPS, точный `public_origin=https://<approved-host>`; прокси сохраняет Host/Origin, не открывает CORS. Cookie `HttpOnly; Secure; SameSite=Strict`, срок не более 90 дней; CSP, no-store, no-referrer, nosniff уже выставляются. HSTS — на HTTPS-прокси после проверки домена.
- Body limit 16 KiB, read/write/idle timeout 10 s, bounded concurrency 32, лимит новых сессий/восстановлений 60/min. Дополнительный общий лимит запросов по фиксированному ключу study-origin, а не IP: например, 10/s с burst 64 в [nginx limit_req](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html). Проверить, что 32 нормальных слушателя не получают отказов. Backend preview имеет только собственный process-local start/resume guard; он не заменяет эту проверку.
- Отключить access logs и логи URL/body/cookies/referrer/User-Agent/IP на приложении, прокси и выбранном хостинге. Health-monitor не должен записывать запросы участников. Провайдер технически видит IP при соединении: проверить его политику/договор и указать это участникам, не обещать сетевую анонимность.
- Приватный admin-доступ по SSH; нет публичного API для списка участников, выгрузки базы или результатов. Не включать debug/traceback. Приложение ничего не скачивает из сети по входным URL.
- Ежедневный `purge-collected` как host timer, даже если web-процесс остановлен. Работающий preview дополнительно удаляет просроченные данные раз в минуту и при обращении к базе. Проверить переход UTC-даты, рестарт и плановое удаление до размещения.

## Локальная проверка сбора

Из `experiments/listening-study`, в отдельном Python-окружении:

```sh
python -m listening_study demo work/collection-demo
python -m listening_study collect work/collection-demo/study.json \
  work/collection-demo/private.sqlite work/collection-demo/collection.demo.json
# Только http://127.0.0.1:8765 — не публичный сервис.
```

Demo создаёт явно фиктивный код SurveyCircle. Настоящий код никогда не коммитить и не включать в артефакты CI. Вторая формулировка выдаётся сервером по заранее воспроизводимому блоку; слушатель её не выбирает.

```sh
python -m listening_study analyze-collected work/collection-demo/study.json \
  work/collection-demo/private.sqlite work/collection-demo/collection.demo.json \
  work/collection-demo/current-aggregate.json
python -m listening_study purge-collected work/collection-demo/study.json \
  work/collection-demo/private.sqlite work/collection-demo/collection.demo.json
```

Отчёт читает текущую базу и сохраняет только агрегаты/интервалы, без UUID и ответов отдельных людей. Нет обязательного download JSON для участника и нет команды создания разрозненных raw exports, которые пережили бы отзыв. Наличие этой команды не разрешает смотреть предпочтения до окончания набора: до закрытия контролировать только технические сбои и число сессий.

Для реального набора нужны отдельные `study_id`, база и private config: `consent_version=collection-consent-v1`, `capacity=32`, рабочий контакт исследователя, точные `intake_closes_on` и `delete_on`, настоящий `surveycircle_code`, согласованный HTTPS-origin. Даты и contact входят в hash конфигурации; нельзя незаметно менять их в существующей базе. Все реальные tracks обязаны иметь подтверждённые `rights.public_reproduction=true` и `rights.delayed_attribution=true` наряду с прежними rights-проверками. Demo не может перейти в pilot переименованием файла.

## Согласие, повторные отправки и удаление

До согласия нет участника, cookie или назначенного slot; отказ на стартовой странице ничего не записывает. После согласия сохраняются: случайный UUIDv4, версия согласия, UTC-дата начала (без времени), версия/хэш исследования, вариант вопроса, slot, ответы, минимальные флаги прослушивания и статус. Имена, email, Яндекс-аккаунты, музыкальные токены, IP, User-Agent, fingerprint и свободный текст не принимаются.

В браузере хранится только необходимый HttpOnly cookie. На старте один раз показывается независимый случайный резервный код (256 бит): его можно сохранить самостоятельно для восстановления/удаления с другого устройства. В базе лежат SHA256 обоих секретов; код не попадает в URL, аналитику или журналы. Восстановление меняет cookie и лишает прежний cookie доступа. Потеря и cookie, и кода означает, что без установления личности найти сессию нельзя — это ограничение сообщается в инструкции.

Каждый ответ сохраняется транзакционно **до** перехода к следующему заданию. Идентичный retry возвращает сохранённый результат, конфликтующий ответ/другое задание отклоняется. Последний ответ ещё не делает сессию завершённой: отдельная кнопка подтверждает включение в исследование. Код SurveyCircle и кредиты выдаются только после завершения; кредиты доступны также после отказа. Пропуски и «Ни одна» сохраняются отдельно. Отмена после завершения остаётся возможной.

Закрытие страницы не является отзывом. Возврат с cookie предлагает продолжение, без автозапуска аудио; подтверждённые ответы остаются, текущий неотправленный выбор/секунды прослушивания нужно повторить. При отсутствии подтверждения от сервера интерфейс не заявляет успешного сохранения или удаления. В частности, при offline-отказе нужно вернуться и повторить отказ; иначе незавершённая сессия истечёт автоматически.

Повторный старт с тем же cookie не выделяет новый slot; повторное завершение не дублирует ответ; один активный/завершённый участник на seat. Сброс cookies, другой браузер или бот могут обойти ограничение. **Это ограничение повторных отправок, не доказательство уникальности человека.** Нет IP-блокировок, CAPTCHA или device fingerprint. Лимит 32 занятых мест, 256 суммарных сессий и intake deadline сдерживают заполнение хранилища; атакующий всё ещё может занять места. В таком случае приостановить набор и разобраться в технических счётчиках, не исключать людей по музыкальным ответам.

Незавершённый raw response удаляется на седьмой календарный день UTC после начала. Завершённые ответы хранятся до заранее указанной `delete_on` (предложение: 90 дней от начала набора). При отказе response/UUID стираются сразу; остаётся только отметка статуса, даты, slot, согласия и хэшей секретов для запрета повторной отправки/идемпотентного отказа. Все эти строки удаляются в `delete_on`. SQLite `secure_delete=ON`, DELETE journal; физическое стирание блоков SSD/снимков этим не гарантируется.

На первом пилоте не делать raw dumps/снапшоты/автобэкапы, которые переживут отзыв. Это снижает устойчивость к потере host: при потере базы набор остановить, не восстанавливать ответы из личных сообщений. Если резервирование понадобится, до запуска отдельно согласовать шифрование, короткий срок, журнал удалений и применение всех отзывов **до** открытия восстановленной базы. Вручную сделанные копии также подлежат удалению. Итоговые агрегаты не позволяют выделить ответ одного человека; отозвать вклад из уже опубликованных агрегатов нельзя. До публикации пересчитать отчёт по текущей базе после всех поступивших отказов.

## Приёмка с 3–5 людьми до SurveyCircle

Это отдельный usability-run: отдельный ID/hash/база, не включать людей или ответы в 32-пилот. Начать с demo; разрешённую музыку использовать только после rights gate. Один сопровождающий фиксирует обезличенный checklist и продолжительность вручную, без записи экрана/голоса и без вопросов о гипотезе.

| Человек | Устройство | Обязательный сценарий |
|---|---|---|
| U1 | Android + Chrome, реальные наушники | Согласие, слышимость всех трёх, выбор, «Ни одна», skip, завершение; не скачивать JSON |
| U2 | iPhone + Safari | Отключить сеть на сохранении, вернуть сеть и повторить; закрыть вкладку, восстановить |
| U3 | Desktop + Zen/Firefox, клавиатура | Tab/focus, возврат после закрытия, отказ посреди сессии, проверить исчезновение ответа |
| U4 (если доступен) | Desktop + Chromium | Последний ответ → закрыть до подтверждения → завершить; повторный старт не создаёт дубликат |
| U5 (если доступен) | Другое устройство/браузер | Восстановить по коду, старый cookie не работает; удалить уже завершённые ответы |

Для минимальных трёх людей объединить U4 с U1, U5 с U2. Проверить обе формулировки, ориентацию, пропуски, комфорт уровня, прослушивание от начала/перемотку, отсутствие названий/жанров, видимость управления на 320–430 px. Записать явные PASS/FAIL и browser/device/version без связи с pilot-ответами. При любой потере подтверждённого ответа, недостоверном сообщении об удалении, раскрытии условий, неслышимом клипе или невозможности завершить на заявленном устройстве — исправление и повтор затронутого сценария до набора. Автоматическая WebKit-эмуляция не заменяет реальный iPhone/наушники.

## Последовательность запуска

1. **Владелец + два проверяющих:** пройти [44 кандидата](CANDIDATES.md), [аудит прав](LICENSE_AUDIT.md) и [план 8 троек с квотами авторов](POOL_FEASIBILITY.md). Установить конкретные права/мастера, разрешить разночтения; неизвестные признаки не заменять отрицательными. Затем ограниченное ручное получение выбранных записей. Если нет 8 валидных троек — расширить pool до начала ответов, не подгонять пороги.
2. **Подготовка:** 24 разных 15-секундных клипа → реальные признаки → независимая ручная оценка → 6 A/B + 2 C/D → freeze pilot-v01. Зафиксировать hashes, seed, правила отбора и код, удержать stem/source artist identity (псевдонимы не независимы).
3. **Владелец подтверждает размещение:** отдельный host/регион/домен, бюджет (в том числе нулевой только при подтверждённом ресурсе), оператора данных/контакт, даты закрытия/удаления, требования организации. Подготовить production-обвязку и проверить HTTPS, логи, purge, нагрузку и восстановление. Не использовать существующий опубликованный Yanjaro или Render.
4. **Закрытый pretest 3–5 человек:** выполнить таблицу. После технических исправлений повторить проверки и заморозить финальную рабочую версию. Не выкладывать demo/beta в каталог SurveyCircle.
5. **Владелец в SurveyCircle:** проверить доступную квоту/географию аккаунта, создать черновик карточки, получить Survey Code, внести его только в private config до создания pilot-базы. [FAQ](https://www.surveycircle.com/en/faq/) поясняет: код выдаётся при создании карточки, ответы находятся у внешнего инструмента. Не обещать 32 бесплатных места — текущая квота видна владельцу при создании ([§4](https://www.surveycircle.com/en/terms/)). Выполнить финальный тест кода на отдельной проверочной конфигурации без погашения своего кода.
6. **Публикация после согласования:** финальный HTTPS URL и нейтральный текст ниже; дополнительные приглашения в разрешённых сообществах. Не отправлять сообщения/письма автоматически. Люди, знающие гипотезу/отбиравшие музыку/участвовавшие в pretest, не входят в пилот.
7. **Набор:** цель 32 завершённые сессии, 16 на вопрос; глобальный cap 32 одновременно занятых/завершённых мест. Сервер выдаёт вопрос блоками по два и slot 0–15. Отказ/истечение освобождает ту же заранее назначенную ячейку для нового человека. Это замена по статусу, никогда по предпочтениям. Отказ после закрытия может уменьшить итоговый N: не продолжать тайно до нужного результата. Закрыть intake через заранее назначенные 30 дней или при 32 завершениях, что раньше; если остаются активные сессии на deadline, разрешить им завершить до их семидневного истечения. Если N меньше, публиковать фактический размер и дисбаланс. После удаления последней карточки не обещать новые SurveyCircle points.
8. **Анализ:** одна зафиксированная процедура по текущим complete-сессиям; вопросы раздельно, participant bootstrap + source sensitivity. Сообщить начатые/complete/withdrawn/expired/in_progress, «Ни одна»/skip и фактический баланс. Никакой оценки гипотезы из demo, исключения «неудобных» ответов или незаметной замены стимулов.
9. **Закрытие:** сразу снять карточку с SurveyCircle после завершения набора (§4), пересчитать финальные агрегаты после отзывов, удалить raw database rows и приватные копии в указанную дату. Пилотные изменения оформить отдельной версией; подтверждающее исследование — на независимой выборке.

## Текст карточки SurveyCircle (черновик)

**Название:** Музыкальные впечатления: короткие прослушивания

**Описание:** Приглашаем совершеннолетних добровольцев в исследование музыкальных впечатлений. Вы услышите короткие отрывки и выберете наиболее подходящий вариант по вопросу на экране. Правильных и неправильных ответов нет. Всего 8 заданий, ориентировочно 8–12 минут; точное время уточним после пробного прохождения. Нужны наушники, тихое место и понимание русского языка. Можно выбрать «Ни одна», пропустить любое задание или отказаться. Имена, контакты и музыкальные аккаунты не требуются; ответы сохраняются под случайным кодом. При возвращении в том же браузере можно продолжить или удалить ответы. Код SurveyCircle появится после завершения исследования. Просим участвовать один раз и не обсуждать задания до окончания набора.

**Поля перед публикацией:** HTTPS URL; имя/контакт ответственного исследователя; даты набора и удаления; язык RU; 18+; длительность по медиане pretest (пока лишь оценка); только проверенные категории устройств. Публиковать честное исследование, не обещать научную валидность, терапевтическую пользу или персональные рекомендации. Не раскрывать жанры, сравнение факторов или условия в названии, preview-картинке, URL и ключевых словах.

Для других площадок тот же текст без предложения о коде SurveyCircle. Проверить местные правила размещения. SurveyCircle — добровольная взаимопомощь, не случайная репрезентативная выборка; склонность выполнять чужие опросы и самовыбор ограничивают переносимость. Смешение каналов и устройств не устраняет это ограничение. 32 — оценка выполнимости, а не доказанная статистическая мощность.
