# Yandex Track ID → акустические признаки: проверка осуществимости

Дата наблюдений: **15 октября 2026**. Результат: **ни одного сквозного пути с подтверждённой записью и допустимым источником признаков в этой проверке не получено**. Это не доказательство отсутствия такого пути вообще. Получены реальные ID, частичные метаданные, внешние кандидаты, один мост между релизами и измеренный результат поиска по открытой таблице датасета.

Работа изолирована в `experiments/track-feasibility/`, ветка `experiment/yandex-acoustic-feasibility-v01`, база `main@1c83c3776de565ed57416015f32a7ddd999af29f`. PR #10/#11, замороженный listening pilot, модели, коэффициенты, плеер, сборка и публикации не менялись. Ничего из результатов пилота не использовано как доказательство сопоставления.

Read-only сверка GitHub до и после исследования: PR #10 open/draft, HEAD `35aecde3311fa302e0ac1548d9c53f336ed9c928`; PR #11 open/draft, HEAD `a9fe148cc9b81fcfb76d55ea11d18b701bbd0e84`; `main` остаётся на указанной базе. Для исследования создан отдельный clone, текущий рабочий каталог с приватными материалами пилота не использовался как источник данных.

Текущая доступность всех 30 записей непосредственно в каталоге **не подтверждена**. Публичное свидетельство существования ID и действующая карточка каталога — разные результаты. Поисковые/веб-инструменты возвращали в том числе кешированные страницы; возраст кеша записан там, где инструмент его сообщил. Shell-проверки Yandex/MusicBrainz остановились на DNS; отдельные страницы MusicBrainz вернули 429. Эти ограничения среды нельзя приписывать всему сервису или всем пользователям.

Выборка сохранена до внешнего сопоставления в коммите `5e84934`. SHA-256 [sample.json](sample.json): `7499bd512e07694e841054f70b7cb58d6bc9d6c1c43489884b8ff656ca3a29d5`. После фиксации ID не заменялись. Это целевая выборка публичных ссылок, 15 российских и 15 зарубежных записей по намерению отбора. Доступность ссылок влияет на отбор; пять записей одного российского артиста и четыре Adele дополнительно ограничивают разнообразие.

«Популярные / менее популярные» — исследовательские категории отбора, **не измеренная популярность**: публичных сопоставимых счётчиков не получено. В выборке есть четыре явных названия с remix на страницах Яндекса, ссылки на синглы и альбомы, отдельная версия 2002 года. **Требование о подтверждённых live-версиях осталось BLOCKED.** У двух записей Русского Размера live относится к соседнему видеопосту; оно не доказывает версию трека по ссылке. ## Проверенные сопоставления и отказ от ложных совпадений

**«Команда», Yandex 149359136.** Публичная ссылка указывает album 41194184. [MusicBrainz release](https://musicbrainz.org/release/6b3724b8-7133-4602-8614-96ad5529cf67) прямо ссылается на тот же Yandex Album ID; трек 7 — «Команда», 2:54, barcode релиза 3618029124569. Из ссылки трека получен recording MBID `9764cc8e-f566-4c7a-bb04-8d6d405237ba`; [страница записей исполнителя](https://musicbrainz.org/artist/1768e417-3deb-47df-907a-1f457562cbd9/recordings) показывает внешний ISRC `FR59R2630848`. Это поддерживает связь релизов. ISRC и длительность **не получены со стороны Яндекса**, содержимое master не сверено, поэтому recording match не присвоен. У новой записи 2026 года также нет оснований предполагать покрытие архивом, прекратившим сбор в 2022 году.

**Blurry, Yandex 70541.** Первичная страница Яндекса подтверждает только Puddle Of Mudd / Blurry. Реально открыт [MusicBrainz recording](https://musicbrainz.org/recording/ec1fc730-72a4-4086-bebf-d957a372382f): album version, 5:04, ISRC `USIR10110581`, Spotify track `0FLBNqc5oAiTt4J2e3fe3y`. [Work](https://musicbrainz.org/work/71bf0918-5c79-4015-aa08-e24d14d46463?direction=2&link_type_id=278) также имеет radio edit 4:20 и другие записи. Выбирать album version без версии/длительности Яндекса нельзя; ISWC идентифицирует произведение, не фонограмму.

Для обоих конкретных recording MBID выполнены запросы документированного AcousticBrainz `/api/v1/{mbid}/low-level`: **ошибка инструмента, payload не получен**. Это не ответ 404 и не измерение отсутствия записи в AcousticBrainz. Пример JSON из документации не засчитывался как результат выборки. Точные URL и исходы сохранены в [web-receipts.json](web-receipts.json).

Другие проверки показывают риск автоматического сопоставления: у Someone Like You найден live-кандидат 5:17 рядом с синглом; выдача Cockiness возвращала оригинальный альбом, хотя Yandex-заголовок говорит Remix; найденная компиляция He Won't Go помечена MusicBrainz как unofficial и отклонена. Blinding Lights у The Weeknd и Alistair Griffin не считаются одной записью. Wikidata связывает ID с сущностью, но это само по себе не проверка master. Даже совпавшие ISRC полезно сверять с исполнителем, версией, длительностью и релизом: ошибка каталога или разные мастеринги остаются возможны.

## Реальная проверка датасета

Получен официальный репозиторий [MTG-Jamendo](https://github.com/MTG/mtg-jamendo-dataset/tree/cafd8e20c265ed84f1e61f1c875327971f43a62f) на commit `cafd8e20c265ed84f1e61f1c875327971f43a62f`. Запущен поиск по `data/raw.meta.tsv`, **без скачивания аудио, спектрограмм или features-архивов**.

Измерено: файл **7 848 074 байта**, SHA-256 `bb1efa2876536cbe1a8b67db5dda15249ca144f0cff69e481b638803cbdc9aca`; 56 639 строк данных, **56 637 обработаны**, 2 отклонены из-за лишнего столбца (строки 29 540 и 29 543). Начальный CSV-парсер интерпретировал буквальные кавычки как разметку; исправлен на буквальное чтение TSV. Повреждённые строки не исправлялись догадкой. Заявленные в README датасета 56 693 строки не подменяют измеренный размер этого файла.

Нормализация: Unicode NFKC, регистр, пробелы. Совпадений **исполнитель + название — 0**; только название — 4 для Blind и 1 для In The Woods, все отклонены как доказательство идентичности. Алиасы/транслитерация и две повреждённые строки не покрыты. Это результат данного алгоритма на данном файле, **не утверждение об отсутствии этих исполнителей во всём Jamendo**. У строки Black coal исполнитель в замороженном входе неизвестен; поиск по паре для неё неполон.

Время одного локального прохода: **0.261998 с**, Python 3.14.7. Это измерение чтения и поиска метаданных, не скорости загрузки, сетевого resolver, DSP, inference или качества сопоставления. Сохранён [jamendo-scan.json](jamendo-scan.json).

FMA проверен по официальному README и структуре репозитория: каталог/feature-архив не загружался, поиск по полному FMA **NOT RUN**. Для остальных источников без recording-level crosswalk проверки наличия векторов для каждого ID также **NOT RUN**, а не «вектора нет». Обзор источника отделён от фактического поиска строк.

Yambda публикует готовые embeddings для миллионов анонимных items; опубликованный объём **не является измеренным пересечением с Yandex ID выборки**. Не предпринимались попытки деанонимизации. CC0-метаданные MusicBrainz также не очищают права на фонограмму, а право прослушивания/покупки само по себе не подтверждает право обработки и долговременного хранения производных признаков.

## Масштаб: 100 тысяч, 1 миллион, 10 миллионов

Все числа ниже — **арифметические сценарии**, не измерения production и не экстраполяция покрытия 30 строк. Доля подходящих записей в каталоге неизвестна; утверждения о 95% нет.

| Предположение / формула | 100 тыс. | 1 млн | 10 млн |
|---|---:|---:|---:|
| 768 float32 на запись: N × 768 × 4, только pooled vectors | 0.3072 GB | 3.072 GB | 30.72 GB |
| 2 KB metadata/provenance на запись (условно) | 0.2 GB | 2 GB | 20 GB |
| Аудио 4 мин, 256 kbit/s: N × 240 × 32 000 | 0.768 TB | 7.68 TB | 76.8 TB |
| PCM mono 48 kHz/16 bit, 4 мин | 2.304 TB | 23.04 TB | 230.4 TB |
| Сохранить 75 frames/s × 768 float32 × 4 мин | 5.5296 TB | 55.296 TB | 552.96 TB |
| CPU 10 секунд/трек, гипотетически | 277.8 ч | 2 777.8 ч | 27 777.8 ч |
| 3 запроса/трек при 1 запросе/с, без повторов и простоев | 3.47 суток | 34.72 суток | 347.22 суток |

GB/TB здесь десятичные. Векторная строка — только ёмкость при выбранной размерности; она не предлагает MERT для коммерции и не означает, что все источники имеют совместимое пространство. Для хранения нужны ещё индексы, версии, контрольные суммы, права, резервные копии и репликация; их множитель не измерен. Для raw JSON AcousticBrainz размер payload зависит от содержимого, измерения здесь нет.

Для CPU общее время = N × t / 3600; параметр t **не измерен**. Если t=1 с, третья величина — 2 777.8 ч вместо 27 777.8. Декодирование, IO и проверка качества добавляются отдельно. GPU и обучение не запускались. Сценарий 75 frames/s/768 взят из спецификации модели, но хранить всю последовательность обычно значительно дороже pooled features.

Сетевая строка иллюстрирует [обычное ограничение MusicBrainz 1 запрос/с](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting), а не измеренный throughput. Массовый поиск через веб-страницы и поисковик не масштабируется; нужны разрешённая выгрузка Yandex/дистрибьютора, локальный индекс CC0 core dump и лицензированный источник признаков. Доступность API, лимиты и права могут оказаться барьером раньше вычислений.

При условном обновлении 1% каталога в день надо проверять 1 тыс./10 тыс./100 тыс. записей в день. При t=10 с это 2.78/27.78/277.78 CPU-часа в день до IO. Нужно учитывать переиздания, смену master при том же внешнем ID, explicit/clean, radio edit, territorially different releases, удаление и отзыв прав. Повторный расчёт разрешён только для разрешённого аудио; новая версия признаков не должна молча заменять старое сопоставление. Стоимость прав, разрешённых выгрузок и поддержания crosswalk **не оценена**: коммерческих предложений и договоров нет.

## Воспроизведение

Нужен только Python 3.11+ standard library. Скрипт не импортирует плеер и не использует сеть, секреты, модели или аудио. Он воспроизводит решения по сохранённым фактическим наблюдениям; сам по себе не обновляет публичные веб-страницы. Положительные acoustic matches этим ограниченным replay не поддерживаются: для них нужны новый протокол и реальные receipts, а не изменение флага.

Из корня репозитория:

```sh
python3 experiments/track-feasibility/check.py > /tmp/track-feasibility-replay.json
cmp experiments/track-feasibility/results.json /tmp/track-feasibility-replay.json
python3 -m unittest discover -s experiments/track-feasibility -v
```

Независимо повторить реальный поиск по metadata-only датасету (отдельный пустой каталог):

```sh
git clone https://github.com/MTG/mtg-jamendo-dataset.git /tmp/mtg-feasibility-replay
git -C /tmp/mtg-feasibility-replay checkout --detach cafd8e20c265ed84f1e61f1c875327971f43a62f
python3 experiments/track-feasibility/check.py --jamendo-metadata /tmp/mtg-feasibility-replay/data/raw.meta.tsv > /tmp/jamendo-replay.json
```

Сравнить SHA-256, число строк, отклонённые строки и `matches` с сохранённым receipt; `seconds` и версия Python ожидаемо различаются. Не запускать download-скрипты датасета. Attribution: MTG-Jamendo Dataset, Music Technology Group, 2019–2023; исходные metadata CC-BY-NC-SA 4.0. Полная таблица здесь не распространяется; опубликованы только результаты проверки и хеши.

Веб-часть повторяется по `discovery_url`, `canonical_probe.url`, `external_search.query`, `external_candidates[].source_url` и `web-receipts.json`; доступность/кеш могут измениться. Для свежего наблюдения сохранять новую дату/ответ отдельно. Ошибка доступа, пустая поисковая выдача и действительный ответ «нет записи» не взаимозаменяемы. Сценарий не содержит обхода региональных ограничений и автоматических повторов запросов.

## Вывод и следующий минимальный эксперимент

**Практически проверенного сквозного пути Yandex Track ID → признаки нужной фонограммы с подтверждёнными правами пока нет.** Проверенные части пути: публичные ID, частичная первичная metadata, реальные внешние сущности, release cross-link, работающий поиск по metadata-таблице. Непроверенные части: точный master и payload с допустимыми правами для этого master.

Следующий минимальный E2E имеет смысл разрешить **для одной принадлежащей автору записи**, а не для всего каталога. До аудиозагрузки получить от автора/дистрибьютора: Yandex Track/Album ID, ISRC, точную версию и длительность, подтверждение что предоставляемый файл — поставленный в каталог master, и разрешение на локальную обработку, хранение/использование признаков, включая коммерческую цель при необходимости. Зафиксировать эти данные и SHA-256 файла; назвать источник и условия удаления/отзыва. Пользователь отдельно разрешает получение одного этого файла. Контакт с автором автоматически не выполнялся.

После такого разрешения: один CPU-only проход уже существующим разрешённым DSP extractor в отдельном эксперименте, без изменения PR #10/#11 и без MERT; сохранить реальный vector с размерностью, версией extractor, input hash, правами и crosswalk receipt. PASS только при полной цепочке идентичности/прав/payload и воспроизводимом повторе на том же файле; при несовпадении версии или неизвестном праве — BLOCKED. Это докажет техническую возможность для одной записи, **не качество рекомендаций и не покрытие каталога**. Если правообладатель не может подтвердить master↔Yandex ID, сначала нужен metadata-only crosswalk, разрешение на аудио само по себе проблему не решит.

Альтернатива без аудиозагрузки — получить первичный recording-level crosswalk для одной старой записи и доступный CC0 payload AcousticBrainz с проверкой submission/version. На текущих двух запросах это не продемонстрировано; считать этот вариант уже работающим нельзя.

Проверки: offline replay и 6 unit-тестов **PASS**; точный recording match и end-to-end acoustic coverage **NOT ESTABLISHED**; audio download/inference/training/GPU/paid services **NOT RUN**. Тесты проверяют учёт доказательств, а не истинность записей каталога. Production/desktop/audio smoke не запускался: код плеера не затронут.
