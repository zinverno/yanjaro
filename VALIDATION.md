## Установленное окружение

- Manjaro x86_64, Wayland; системный Python 3.14.7 не изменён.
- Изолированная `.venv`: существующий uv-managed CPython 3.13.13; PySide6-Essentials / Shiboken 6.11.2, python-mpv 1.0.8, yandex-music 3.2.0. Все зависимости зафиксированы в `requirements.lock` с SHA-256.
- Настоящий libmpv сообщает `mpv v0.41.0`. Он распакован в `.runtime` из пакета Manjaro; системная установка пакетов не выполнялась.
- Автоматический desktop-прогон использует Qt `offscreen`, аудиовыход `null`. Внешний вид пустого окна просмотрен в offscreen-режиме; это не live-проверка аккаунта или графической сессии пользователя.
- Попытка запуска `./run.sh` из sandbox завершилась с кодом 134: `Failed to create wl_display (Operation not permitted)`, затем X11 `could not connect to display :0`. Пользователь подтвердил, что окно не появилось. Сокеты Wayland/X11 существуют, но доступ из процесса sandbox запрещён. Пользователю передана команда запуска из обычного терминала. Установка дополнительных Qt-плагинов на основании этого сообщения не требовалась.
- **Подтверждение пользователя:** после запуска той же сборки из обычного терминала окно появилось. Результаты аккаунтных сценариев приведены отдельно в таблице.
- В sandbox процесса разработки DNS `api.music.yandex.net` возвращает `EAI_AGAIN` (`errno -3`). Анонимный запрос SDK завершился `NetworkError`. Это проверка сетевой доступности среды, не проверка аккаунта. Для live-проверки клиент нужно запустить из обычного терминала пользователя.

## Локальные native-пакеты

Скачаны с настроенного зеркала Manjaro `https://www.mirrorservice.org/sites/repo.manjaro.org/repos/stable/extra/x86_64/`. SHA-256 каждого архива сверялся с локальной базой pacman `/var/lib/pacman/sync/extra.db` перед распаковкой. База pacman не изменялась.

- `mpv-1:0.41.0-6-x86_64.pkg.tar.zst`
- `mujs-1.3.9-1-x86_64.pkg.tar.zst`
- `libsixel-1.10.5-1-x86_64.pkg.tar.zst`
- `libxpresent-1.0.2-1-x86_64.pkg.tar.zst`

В локальной копии `libmpv.so.2` выполнено `patchelf --replace-needed /usr/lib/libmujs.so libmujs.so`: исходный пакет ссылается на абсолютный системный путь. Это позволяет загрузить распакованный MuJS через `LD_LIBRARY_PATH`. Другие системные зависимости используются как есть. Не переносите `.runtime` на машину с другим ABI без повторной проверки.

## Результат живой проверки

Пользователь подтвердил появление окна при запуске из обычного терминала, затем сообщил: «Вход выполнен, мои треки появились». На запрос проверки поиска, звука, паузы/продолжения, перемотки дальше 30 секунд и отдельного прослушивания от начала до естественного конца ответил: «Да, всё работает, трек доиграл целиком». Это ручная live-проверка пользователем; агент не получал токен, код или содержимое библиотеки.

Второй этап: пользователь уточнил «Все кроме истории работает, в истории неправильные песни», затем пояснил: «Старые знакомые треки, новые не появились». Каталог, запуск волны и следующая партия подтверждены; серверная история читалась, но новые прослушивания в ней не появлялись.

В первоначальном клиенте отсутствовал вызов `play-audio`: были только чтение истории и feedback волны. Добавлена отправка фактического прослушанного времени при EOF, смене трека и закрытии клиента, с отдельным play ID и исходным временем начала. Перемотка и паузы не засчитываются; повторное событие окончания не создаёт повторный отчёт. На повторную проверку после перезапуска, полного прослушивания и обновления истории пользователь ответил: «Не появился, ошибок нет». Добавление отправки не устранило наблюдаемую проблему; отсутствие ошибки не доказывает приём события или запись в историю.

После этого добавлен отдельный статус отправки события в разделе истории. Он различает успешный ответ и безопасное сообщение об ошибке; текст явно отделяет приём события от обновления истории. Эта последняя правка проверена автоматически, но ещё не проверена пользователем с аккаунтом. В истории остаются только серверные данные, без добавления локальных прослушиваний для имитации результата.

Автор другого неофициального клиента [YaMusic описывает похожее наблюдение](https://github.com/andfriden/YaMusic#история-прослушивания): события получают успешные ответы, но не добавляют записи в `music-history`. Это свидетельство автора стороннего клиента, а не официальная гарантия Яндекса и не доказанная причина нашего случая. Синхронизация устройств / Ynison не добавлялась.

Минимум для подтверждения полного сценария: реальный вход → библиотека → поиск → слышимое воспроизведение → pause/resume → seek за 30 секунд → отдельное полное прослушивание до EOF; затем каталог станций → волна → успешная новая партия → серверная история. Не включать в отчёт токены, коды входа, имена аккаунтов или временные аудиоссылки.
